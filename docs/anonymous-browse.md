# 匿名浏览：未登录也能进应用

> **状态：已实现。** 2026-10-08 提出，同日落地。
> 起因：登录弹窗关不掉 —— `LoginPage.xaml.cs` 里明确挡着 Esc，注释写着「现有外壳需要登录才能使用」。
> 但那个前提本身值得推翻，而不是给它加个「退出应用」按钮。
>
> 实现与本文的四处差异：
> 1. **登录框不再是一页。** 第一版把 `LoginPage` 压进导航栈当宿主，结果它把自己锁死了：
>    窗口一隐藏到托盘，`ContentDialog` 的弹层就没了，但它逻辑上还开着 ——
>    `ShowAsync` 永不返回、退栈永不执行，那一页永远留在栈顶，此后
>    `Navigate<LoginPage>` 被「当前页已经是这个页面」静默挡掉，**再也打不开**。
>    现在它是 `Controls/LoginDialogContent`（内容）+ `Controls/LoginDialog`（宿主），
>    挂在外壳的 `XamlRoot` 上、**每次打开新建一个**、不碰导航栈 —— 结构上没有可卡住的状态。
> 2. **登录成功后不跳「我喜欢的」，留在当前页。** 打开与关闭都不改变用户所在的页面
>    （连退栈都不需要了）。
> 3. **守卫拦下时抛的是一个新类型** `BodianNotSignedInException`（派生自 `InvalidOperationException`）。
>    原来是一句裸的 `InvalidOperationException("曲库接口需要登录后才能调用。")`，异常文案会直接
>    漏进界面的「加载失败：…」。分成类型之后，界面能说「登录后可查看」并且**不给重试按钮**
>    （重试还是同一个结果）。
> 4. **「我的音乐」分组头跟着一起藏**，见第七节的第 6 条。

## 问题

应用**强制登录**：没有会话就 `ShowLogin()`，把侧栏、搜索框、账号入口全收掉，只留一个关不掉的弹窗。
于是用户面对的是一个死胡同 —— 不想登录就只能退应用。

当初这么定的理由是「外壳需要登录」。可这个理由**只对播放成立**：

| 能力 | 未登录时 |
| --- | --- |
| 搜索、榜单、乐库、首页 | ✅ 接口本就是匿名形态（`uid=-1`、`token` 空串，`bodian-api-reference.md` 里大量端点都是匿名实测的） |
| 评论、回复、歌词、MV 列表 | ✅ 同上 |
| **播放** | ❌ 服务端一律 `code 20018`「没有解锁付费歌曲」，`checkRight` 返回 `status=7` → 客户端报 `NotAuthenticated` |
| 喜欢 / 收藏 / 关注 / 自建歌单 | ❌ 要登录 |

也就是说匿名态**能搜能看、不能听**。这不是「外壳被登录绑住」，是「播放被登录绑住」——
把整个外壳一起锁起来是把结论下大了。

## 一、关闭按钮的语义（本次的起因）

**加了匿名模式之后，「关闭」就只有一个意思：离开弹窗，留在应用里。**

| 从哪打开 | 关闭之后 |
| --- | --- |
| 启动时（无会话） | 进外壳，未登录态：能搜能看，点播放提示「登录后可播放完整歌曲」 |
| 「添加账号」 | 回到**原来那个账号**（因为添加账号不再先登出，见第三节） |
| 首次启动的自动弹窗 | 进外壳，未登录态；不再自动弹 |

**不再需要「退出应用」这种重语义**，也不需要「按 Esc 就退出」这种吓人的行为 ——
Esc 直接放行，等同关闭。

关闭入口是**右上角那颗 ✕**（与页签同一行，不额外占一行高度）。
**没有用 `ContentDialog` 自带的 `CloseButtonText`**：那颗固定在底部，位置压不住。
代价是 Esc 不再由框架处理（框架的「Esc → 关闭按钮」是绑在那颗按钮上的），
改由 `LoginDialogContent.OnKeyDown` 自己接一次，键盘用户不受影响。

弹窗里另有一行说明：「不登录也能搜索、浏览；登录后才能播放与同步歌单」——
关闭是个中性动作，不说清的话用户会以为关掉就没得玩了，那正是这次要修的误解。

**启动时自动弹一次**（用户已确认），关掉之后本次运行不再自动弹；
要登录就去账号入口点。

## 二、为什么要匿名模式才能这么干

如果外壳仍然需要登录，那「关闭」就只能在「退出应用」和「留在一个空页面」之间二选一 ——
前者在「添加账号」这条路上荒谬（用户只是想反悔，却把应用关了），后者是现在这个死胡同。

匿名模式把这两难拆掉了：**关闭之后总有一个可用的界面**。

## 三、「添加账号」不再先登出

现在的实现是 `AccountViewModel.AddAccount()` → `_login.SignOut()` → 弹登录框。
先登出是因为登录宿主是「必须有会话才能离开」的那个页；现在登录框只是一个可在任意时刻打开的弹窗，
就没有理由先拆掉当前的会话。

改成：**已登录状态下直接打开登录框**；登录成功后 `Adopt` 会接管会话（新账号进记住的清单、
队列与历史跟着切、侧栏重拉）。取消 = 什么都没发生。

顺带修掉一个已有的别扭：旧实现在登录成功后会 `NavigateRoot<FavoritesPage>()`。
从外壳里打开的那种场景不该跳走（用户原来在看什么就留在什么），
所以**登录成功后只是把弹窗关掉**，页面一动不动 —— 外壳会自己因会话变更重拉。

## 四、登出与失效也回到匿名外壳

- **登出**：不再 `Reset<LoginPage>()`，改为进匿名外壳（侧栏收起登录才有的项、账号入口变「未登录」）。
- **被服务端判死（11012）**：同样的匿名外壳，另加那条既有的「该账号的登录已失效，请重新登录」提示。

三者（未登录启动、登出、判死）收敛到同一个状态，不是三条各写一遍的路径。

## 五、未登录时各处显示成什么

| 位置 | 未登录态 |
| --- | --- |
| 侧栏：发现 / 排行榜 / 乐库 / 最近播放 | 保留（都能用；最近播放读的是本地匿名桶） |
| 侧栏：我喜欢的 / 收藏的歌单 / 收藏的专辑 / 关注的歌手 | **隐藏**（点进去只会是空的或报错） |
| 侧栏：「创建的歌单」整段 | **隐藏**（要登录） |
| 账号入口 | **位置不变，但图标换成人形** —— 原来是个空灰圆，看不出那是个入口。点开是**已记住的账号列表**（点一下即切，与已登录时的「切换账号」同一套）+ 一颗「登录」。刚登出的人要的是「换一个账号回来」，所以未登录时列表直接摆在最前面，见 [`account-switch.md`](account-switch.md) |
| 播放条 | 照常显示；点播放走既有的 `Denied(NotAuthenticated)` → 「登录后可播放完整歌曲」 |
| 队列 / 音量 / 播放模式 / 最近播放 | 照常（本地数据，按 `anonymous` 作用域存） |

## 六、开放问题

| # | 问题 | 结论 |
| --- | --- | --- |
| 1 | 首次启动要不要自动弹一次登录框 | **要**，且可关闭；关掉之后本次运行不再自动弹（用户已确认） |
| 2 | 关闭入口放哪 | **弹窗右上角的 ✕**（用户已确认；原设计写的是底部一颗「关闭」，位置压不住）。见第一节 |
| 3 | 登录才有的侧栏项是隐藏还是留个灰项 | **隐藏**。四个项（我喜欢的 / 收藏的歌单 / 收藏的专辑 / 关注的歌手）都点不出东西；留灰项等于给一个点了没用的入口。代价是「我的音乐」那个分组头会变成孤儿标题，要连它一起藏 |
| 4 | 未登录时点需要登录的功能（喜欢/收藏/关注） | 走既有的 `NotAuthenticated` 提示（如「登录后可以喜欢。」），不静默失败 |

## 七、改动清单

### 先决条件：曲库守卫过宽（已实测确认）

`BodianApi.RequireAuthenticated()` 被 `GetPlaylistTracksAsync` 无条件调用，注释给的理由是
「`source=5` 是账号歌单，匿名会话下服务端只会回空」。但守卫是**一刀切**的，连公开歌单一起挡。

**2026-10-08 实测（匿名，探针 `call`）**：

| `source` | 匿名结果 |
| --- | --- |
| `4`（公开集合） | HTTP 200 / `total=134` ✅ |
| `13`（发现页歌单） | HTTP 200 / `total=27` ✅ |
| `5`（账号歌单） | HTTP 200 / `total=1`（不是真实数量，等于拿不到） |

结论：**服务端对公开歌单的曲目是放行的，那道守卫挡掉了服务端允许的东西**。
放宽到只对 `source = 5` 校验（且不再是抛异常，而是走「登录后可见」的既有提示），
否则发现页/搜索里点进任何歌单都是「加载失败：曲库接口需要登录后才能调用。」——
匿名浏览就只剩封面和标题，等于没有。

### 「不改就会坏」

| # | 位置 | 改什么 |
| --- | --- | --- |
| 1 | `BodianApi.GetPlaylistTracksAsync` | 守卫放宽到只对 `source = 5` 生效；拦下时抛 `BodianNotSignedInException`，由 `PlaylistTracksViewModel` / `SidebarViewModel` 翻成「登录后可查看」而不是「加载失败」（**权限仍由服务端裁决，这里只是不再拿客户端抛出的异常当提示**） |
| 2 | `MainWindow.OnHostLoaded` | 恢复会话失败时不再 `ShowLogin()`；改为进匿名外壳 + 弹一次可关闭的登录框，落点是**发现页**（不能是 `FavoritesPage`） |
| 3 | `MainWindow.ShowShell` / `ShowLogin` | 增加第三条路「匿名外壳」：侧栏开、搜索框开、账号入口显示成「登录」。`ShowShell` 现在无条件把账号按钮设为可见，会直接露出「已登录」的假象 |
| 4 | `AccountViewModel.AccountText` | 去掉 `?? "已登录"` 这个**谎言**（它是账号按钮的 ToolTip 与弹层标题的来源） |
| 5 | `MainWindow.OnAccountChanged` 的未登录分支 | 区分「从已登录掉出来」（提示登录已失效）与「本来就是匿名」（什么都不说、也别拆外壳） |
| 6 | 侧栏 4 个账号级项 + 「我的音乐」分组头 | 按登录态显隐。分组头（`MainWindow.xaml` 那个 `NavigationViewItemHeader`）**没有 `x:Name`**，必须先起名，否则藏掉子项会留下一个吊在半空的孤儿标题 |

### 「不改只是不完美」

| # | 位置 | 改什么 |
| --- | --- | --- |
| 7 | 账号弹层的「切换账号 / 退出登录」 | 匿名时三块已登录内容（头像行 / 统计 / 两颗按钮）各自带 `SignedInVisibility` 收起来，换成一块「未登录 + 登录」 |
| 8 | 歌单/专辑/歌手详情的收藏、关注按钮 | 匿名可点，失败落到通用文案「收藏失败」；统一到既有的「登录后可以收藏」家族 |
| 9 | 账号头像 | 匿名时给个占位，别是一个灰圆 |
| 10 | 迷你播放器 / 桌面歌词 | 从未播放过时是空窗（非匿名特有，但匿名下更常见） |

### 开箱即用、不用动

发现 / 乐库 / 排行榜 / 搜索 / 评论 / 歌词的接口都不校验登录，匿名字段照常返回；
评论那一套的未登录分支（`登录后可以评论、回复和点赞`、`登录后可以点赞。`）**已经写好且已接线**；
队列、音量、播放模式、最近播放本就按 `anonymous` 作用域存；登录提示文案基本齐全
（`登录后可播放完整歌曲` 等）。

## 八、验收清单（实现后）

1. 全新环境启动（无 `session.dat`）→ 弹一次登录框 → 点「关闭」→ **进得去**，看到发现页。
2. 匿名下：搜索 ✅、点进公开歌单**能看到曲目**（不再是「加载失败」）、排行榜/乐库/最近播放 ✅。
3. 匿名下点播放 → 提示「登录后可播放完整歌曲」，不崩、不静默。
4. 匿名下侧栏**没有**「我喜欢的 / 收藏的歌单 / 收藏的专辑 / 关注的歌手」，也**没有**「我的音乐」这个孤儿分组头。
5. 账号入口显示「登录」（不是「已登录」），点开只有「登录」。
6. 登录 → 侧栏四项与「创建的歌单」段回来；再「添加账号」→ 关掉弹窗 → **还在原账号上，界面没跳走**。
7. 「退出登录」→ 回到匿名外壳（不是登录页），且不弹「登录已失效」。
8. 匿名下播放历史进 `accounts\anonymous\`；登录后不被并进账号那份。
9. 匿名下播放队列、音量、播放模式照常落盘与恢复。
