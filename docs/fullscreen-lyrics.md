# 全屏歌词实现与验收

**更新日期：2026-10-01。** 当前视觉与交互已由用户确认，进一步性能优化留到后续。

本轮以本地 `F:\My_Project\LyciaMusic` 的全屏播放器为参考，在 WinUI 3 中实现沉浸歌词。
歌词页覆盖整个窗口客户区，替换此前嵌在内容区中的歌词设计。显示器全屏由页面按钮或 `F11` 切换。
沿用现有播放引擎、歌词请求、解析、缓存和导航栈，渲染采用原生 Win2D 与 Windows Composition。

## 界面与操作

封面背景经过模糊并在切歌时淡入淡出，歌词透明叠加其上，没有单独的黑色背景。
左侧显示封面及曲目信息，右侧显示大字歌词，底部提供进度、上一首、播放暂停、下一首和音量。
进入歌词页时隐藏原应用标题栏、侧栏和底部播放条；返回后恢复原来的页面实例和窗口外壳。

| 操作 | 行为 |
| --- | --- |
| 点击原播放条的封面或歌词按钮 | 打开沉浸歌词 |
| `F11` 或全屏按钮 | 切换显示器全屏；退出时恢复原窗口呈现器 |
| `Esc` | 全屏时先退出全屏；普通窗口下收起歌词 |
| `Space` | 播放或暂停；键盘操作滑条时保留滑条自己的行为 |
| 鼠标滚轮 | 浏览前后歌词，暂时停止自动跟随 |
| 按住歌词区域拖动 | 浏览歌词；超过 6 DIP 的拖动不会误触播放跳转 |
| 点击某一句歌词 | 跳到该句起始时间，并请求恢复播放跟随 |
| 点击“回到当前歌词” | 结束浏览并回到正在播放的歌词 |
| 浏览后空闲 | 约 4 秒后恢复跟随；浏览时继续移动鼠标会延长等待 |

全屏模式下，顶部及底部操作区在空闲约 3 秒后淡出，鼠标活动后重新出现。
进度拖动期间暂停来自播放器的滑块更新，结束后提交一次跳转。

## 歌词效果与浏览焦点

自动播放时，播放行作为视觉焦点，中心停在歌词视口高度的约 42%。
各行独立保留弹簧的位置与速度，换行后按距离错峰接续；当前行放大，远处行渐模糊，视口上下边缘渐隐。
字号随窗口变化，基本取窗口高度的 5% 与宽度的 2.5% 中较大的值，并限制在 24–80 DIP。

逐字高亮通过渐变画刷连续推进到字形内部。文本按 Unicode 文本元素拆分，音节进度按实际字形宽度分配，
组合字符和代理对不会被当作两个独立字形。逐行歌词仅高亮当前行，不把整句当成长音。

持续至少 1 秒的逐字音节增加浮动、放大及发光。回落动画与已唱状态分开：
同一播放段内，已经点亮的部分保持点亮；播放时钟的小幅向后校正不能让高亮收回或让当前行反复切换。
明确跳转或切歌时重新计算高亮；长音的渐变坐标与其实际绘制位置保持一致。

**浏览行与播放行是两个概念。** 滚动浏览时，位于显示锚点附近的歌词成为清晰的浏览焦点，
模糊距离围绕浏览行计算。鼠标悬停的句子也会清晰显示，方便选句。
浏览不会改变播放位置；点击一句后才按该句时间轴跳转。
不能继续围绕离开视口的播放行计算模糊，否则滑远后所有可见歌词都会模糊。

## 代码结构

| 位置 | 职责 |
| --- | --- |
| `src/Bodian.WinUI/Views/LyricsPage.xaml(.cs)` | 沉浸布局、响应式字号、播放控制、快捷键、操作区显隐 |
| `src/Bodian.WinUI/MainWindow.xaml(.cs)` | 独立 `ImmersiveHost`、标题栏切换、全屏呈现器恢复；不保存全屏尺寸 |
| `src/Bodian.WinUI/Services/NavigationService.cs` | 根据页面选择普通或沉浸宿主，继续使用同一返回栈 |
| `src/Bodian.WinUI/Controls/LyricsBackdrop.cs` | 封面解码、模糊、淡入淡出与切歌结果代次检查 |
| `src/Bodian.WinUI/Controls/LyricsCanvasView.xaml(.cs)` | 透明合成表面、绘制生命周期、播放时钟及滚轮/拖动/点击事件 |
| `src/Bodian.WinUI/LyricRenderer/LyricsRenderer.cs` | 播放焦点与浏览焦点、逐字渐变、长音、边缘羽化及点击命中 |
| `src/Bodian.WinUI/LyricRenderer/LyricsLayout.cs` | 文本排版、字形到音节映射、独立长音排版、缓存资源释放 |
| `src/Bodian.WinUI/LyricRenderer/LyricsScrollAnimator.cs` | 各行的位置、速度和错峰弹簧 |
| `src/Bodian.Core/Models/Lyrics/LyricMotionMath.cs` | 弹簧、单向高亮、浏览行选择、字形扫光的纯数学 |
| `tests/Bodian.Core.Tests/LyricMotionMathTests.cs` | 帧率差异、目标切换、时间校正、浏览焦点及字宽分配回归 |

`LyricsCanvasView` 通过 `CanvasComposition.CreateCompositionGraphicsDevice` 创建
`CompositionDrawingSurface`，像素格式为 `B8G8R8A8UIntNormalized`，使用预乘透明度。
在 `CompositionTarget.Rendering` 中直接绘制并提交，避免额外的 `CanvasControl.Invalidate` 调度。
表面按 `XamlRoot.RasterizationScale` 换算物理像素，DPI 或视口变化时调整尺寸。

原有 `LyricsPlaybackClock` 继续把播放引擎约 5 Hz 的上报插值成连续时间。
渲染器额外限制正常播放中的高亮位置单向推进，点击跳转强制同步时钟。
页面不可见或离场时停止绘制订阅；离场释放表面与排版资源。设备丢失时重建资源的路径已接入，尚未强制模拟验收。

## 本轮修复记录

| 问题 | 原因与处理 |
| --- | --- |
| 点击歌词后异常 | 背景控件在 `Loaded` 时读取尚未建立的设备；改在 `CreateResources` 获取设备 |
| 进入后原生渲染异常 | 延迟绘图引用的效果链被后续修改；各行持有独立、稳定的效果资源 |
| 歌词区域黑底 | 改用显式预乘透明度的 Composition 绘图表面，截图确认封面背景贯穿歌词区 |
| 长音回落后变暗 | 渐变采用了独立排版原点而非实际绘制位置；统一到行内字形坐标 |
| 高亮回退、换行抽动 | 阻止正常时间校正回退高亮；错峰等待期间继续积分原弹簧运动 |
| 滚远后所有歌词模糊 | 浏览焦点改为显示锚点附近的行，悬停行也保持清晰 |
| 浏览后点击未跳转 | 点击由完整 `Tapped` 手势识别；拖动与点击分开，命中使用当前视觉位置 |

## 验证

```powershell
dotnet build Bodian.sln -c Debug --no-restore
dotnet test --project tests/Bodian.Core.Tests/Bodian.Core.Tests.csproj --no-restore
```

构建通过，保留既有 `AiPlaylistPage.xaml:28` 的 `WMC1506` 绑定警告。
核心测试共 546 个，全部通过、无跳过；覆盖弹簧、扫光、高亮不回退及浏览焦点。

运行检查使用真实曲目及 UI Automation/鼠标输入，确认：

- 歌词能持续显示，透明背景没有黑色矩形，反复进入后窗口仍响应。
- 全屏窗口从普通窗口切换到显示器尺寸，退出后恢复原尺寸，返回后侧栏恢复。
- 滚轮浏览显示清晰歌词，点击后播放进度从约 5.7 秒跳到所选句的 38 秒，日志记录行 22 的起始时间。
- 用户确认当前歌词效果及浏览、点击行为可用。

## 后续工作

**当前不继续调参或扩大性能优化范围。** 本机 Debug 短时测量从旧 UI 画布路径的约 23–27 fps，
提升到直接透明合成路径的约 51–53 fps；这些是局部样本，不代表所有歌曲和屏幕尺寸的稳定帧率。
首轮排版仍有耗时，性能问题按用户决定留到后续。

未来按窗口尺寸、DPI、可见行数、长音数分别测量，并关注首帧、换行和拖动的长帧。
诊断可在启动前临时设置 `$env:BODIAN_LYRICS_DIAGNOSTICS = '1'`，日志约每 5 秒输出实际绘制帧率、
平均/最大绘制耗时与最大帧间隔；默认关闭。不要仅修改弹簧参数来掩盖掉帧。

桌面悬浮歌词仍属于 P6，不在本轮范围。单独的翻译/音译排版与歌词设置面板也未接入。
