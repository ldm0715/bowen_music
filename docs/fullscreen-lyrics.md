# 全屏歌词实现与验收

2026-10-07 补充：播放条进入歌词页时，小封面放大到页内大封面；收起时缩回播放条。首次绑定/布局、封面交接与 MV 直接退出的规则见 [应用动画](animations.md)。

**更新日期：2026-10-05。** 用户已确认本轮歌词高亮与位移不再抖动，原因与最终验证见文末复盘。
2026-10-03 的音质入口、收藏／分享统计和顶部 VIP 标识记录保留在下文，验收范围按各自记录说明。

本轮以本地 `F:\My_Project\LyciaMusic` 的全屏播放器为参考，在 WinUI 3 中实现沉浸歌词。
歌词页覆盖整个窗口客户区，替换此前嵌在内容区中的歌词设计。显示器全屏由页面按钮或 `F11` 切换。
沿用现有播放引擎、歌词请求、解析、缓存和导航栈，渲染采用原生 Win2D 与 Windows Composition。

## 界面与操作

封面背景经过模糊并在切歌时淡入淡出，歌词透明叠加其上，没有单独的黑色背景。
顶部居中显示“歌名 - 歌手”，下一行显示专辑名；封面下方不再重复显示曲目信息。
左侧显示封面及水面倒影，右侧显示大字歌词。通栏进度条位于底部控制区上沿，频谱条位于进度条上方，
底栏提供上一首、播放暂停、下一首、收藏 / 分享统计按钮、更多、评论、音质切换、音量与试听标记。
VIP / 付费标识位于顶部「歌名 - 歌手」标题旁，左下角改为收藏和分享入口。
全屏按钮紧邻最小化按钮左侧，与原生窗口按钮统一为 48 DIP 高度；移除标题栏模板额外的 48 DIP 拖动留白。
进入歌词页时隐藏原应用标题栏、侧栏和底部播放条；返回后恢复原来的页面实例和窗口外壳。
下层的常规页在歌词 / MV 显示期间一直留在 `PageHost` 里，进出沉浸页不会向它发
`OnNavigatedFrom` / `OnNavigatedTo`，因此收起歌词不会让「最近播放」之类的页面重新加载或跳回顶部。
歌词页是统一返回按钮的例外：左上角保留原来的 ↓ 收起按钮及其 36×36 DIP 样式，
不移入搜索框旁的返回按钮。收起按钮和普通窗口下的 `Esc` 共用主窗口 `GoBack()`，
关闭搜索浮层并将焦点放回返回页面，避免退出歌词后误展开搜索。

| --- | --- |

| 鼠标滚轮 | 浏览前后歌词，暂时停止自动跟随 |

| 点击“回到当前歌词” | 结束浏览并回到正在播放的歌词 |
| 浏览后空闲 | 约 4 秒后恢复跟随；浏览时继续移动鼠标会延长等待 |

**显示器全屏改用系统呈现器（2026-10-24）。** 此前是手写窗口样式：清掉 `WS_CAPTION` / `WS_THICKFRAME` /
`WS_MAXIMIZE` 后把窗口设到显示器 `OuterBounds`。矩形确实铺满了屏幕，但任务栏是置顶窗口，
仍会压在窗口上方，表现为「窗口全屏了，任务栏还在」。现在改为
`AppWindow.SetPresenter(AppWindowPresenterKind.FullScreen)`，由系统负责隐藏任务栏与边框；
退出时切回进入前保存的 `OverlappedPresenter`，再用保存的 `WINDOWPLACEMENT` 恢复原来的位置、
尺寸与最大化状态。歌词页与 MV 页共用 `ToggleImmersiveFullscreenAsync`，两边同时生效。

普通窗口和显示器全屏均支持自动收起：鼠标离开顶部或底部操作区域 3 秒后，顶栏、曲目信息、
底栏及原生窗口按钮淡出。封面、倒影与歌词继续显示，进度条及频谱保留并降到 25% 不透明度。
鼠标返回顶部（含原生窗口按钮）或底部操作区域时恢复；在封面或歌词区域移动不会反复唤醒操作栏。
悬停操作区域、拖动进度或音量、键盘聚焦操作控件时保持显示。隐藏操作栏不改变页面布局。
鼠标区域判断每 200 ms 校验一次实际屏幕光标与窗口命中，避免非全屏标题栏遗漏离开事件后一直保持悬停。
只有实际键盘操作才启用焦点保护，页面打开时自动分配的焦点不会阻止收起。
普通窗口的最小化、最大化和关闭按钮通过 `OverlappedPresenter.SetBorderAndTitleBar` 真正移除原生标题栏，
保留原有窗口边框。鼠标返回顶部、切换全屏或退出歌词页时恢复原来的标题栏设置。
原先仅将按钮前景色设为透明的方式已移除，避免系统仍绘制窗口按钮。
参考 LyciaMusic 的原始等待时间为顶栏 2.5 秒、底栏 2 秒；本项目按用户要求统一为 3 秒。
进度拖动期间暂停来自播放器的滑块更新，结束后提交一次跳转。

## 音质入口（2026-10-03）

音质按钮位于底栏评论按钮右侧、音量控件左侧，只显示当前「标准」「HQ」「SQ」档位名，
大小与降级详情保留在悬停提示中。音质入口不再位于底栏左侧的付费 / 试听信息区。

菜单复用底部播放器的 `AudioQualityPicker` 与共享 `PlayerViewModel`：内容宽度 160 DIP，
每档保留真实文件大小，选中状态用背景高亮而不显示勾选或强调线。没有音源的档位和试听期间禁用切换。
切换成功只更新音源与音质状态，不重复加载歌词或重置播放历史；失败继续原音源。

高级三档依赖官方手机客户端，不在菜单显示。此次按钮位置与弹层已构建通过，
仍需人工确认打开 / 关闭、选中背景及窄窗口下与中央控制区的间距。

## 更多入口（2026-10-05）

底栏最左端（音量控件那一组的开头）加了一颗常显的「更多」。放这一端是为了让音量继续守在
屏幕最右角；整组右锚定，所以加一颗**不会移动中间传输键的整窗中线** ——
`ControlDeck` 的行高与边距一个都没动，那条「播放键与播放条同高」的算式仍然成立。

菜单与曲目行尾那颗「更多」**同源**（`Controls/TrackActionsMenu`），所以
查看歌手 / 查看专辑、加入歌单这些不必在这一页重写一遍；其中「查看歌手」在合唱曲目上
同样会弹出多歌手选择框。无曲目时整颗折叠 —— 常显的意思是不靠悬停出现，不是没歌也显示。

**但这一份要少几项**（`Scope="Player"`）：曲目行那份的头三项 ——「我喜欢 / 下一首播放 /
加入播放队列」—— 在这一页是多余的。左下角本来就有颗带计数的收藏按钮，另两项对一首
**已经在放**的歌也没什么用。所以这一页只剩「添加到歌单 / 播放 MV / 查看歌手 / 查看专辑」。

两个必须记住的点：

- **Flyout 是 popup，不受自动收起那套管控。** 菜单开着时 `_moreFlyoutOpen` 必须和
  `_volumePopupOpen` 一样进早退守卫，否则操作栏一淡出就剩一个悬空的菜单挂在屏幕上。
- **切歌时重建菜单并把它收起来**，否则会出现「菜单里的歌和正在播的歌对不上」。
- **弹层主题不跟页面的固定深色（2026-10-23）**：`LyricsPage` 是 `RequestedTheme="Dark"`，
  Flyout 与音量弹层原先会继承深色。现在打开时由 `PopupTheme.Apply` 把应用实际主题设到
  内容与 `FlyoutPresenter` 上；`MvPage` 同一条路。

设计取舍、内联链接的样式与两处抽取见 [`ui-refresh.md`](ui-refresh.md) §27。

## 进度条、频谱与封面倒影

进度条保留原生 Slider 的拖动和键盘行为，轨道从原先居中的短滑条改为通栏白色细线。
通常轨道高 2 DIP，悬停、拖动或键盘聚焦时增至 5 DIP，并显示 14 DIP 的白色滑块。
播放时间不常驻；悬停或拖动时以独立浮层显示目标时间和总时长。底部播放控制仍位于进度条下方。

频谱来自 `NAudio.Wasapi` 2.2.1 的 WASAPI 输出回环采样，使用默认多媒体输出设备，
分析其混合输出，其他应用的声音也可能进入频谱。音频仅在内存中分析，不写音频文件。
当前采样没有接入 libmpv 的独立 PCM 输出；后续若要求仅分析本客户端，需要另行接入。

`AudioSpectrumAnalyzer` 使用 2048 点 Hann 窗与 FFT，归并为约 40 Hz–16 kHz 的 48 个对数频段，
再由界面插值为 112 根蓝灰色细柱。频谱最多按 30 fps 刷新，采用快上升、慢回落的平滑效果，
暂停时回落到低亮度基线。只在歌词页可见且播放中启动采样；切走、不可见或暂停时停止采样。
采样不可用时保持静态基线，不影响音频播放和歌词。

封面倒影按用户修正采用水面效果，取消斜切和平行四边形轮廓。
封面垂直翻转后从底边向下延伸，边缘和下方柔和渐隐；水平波纹随深度增强，按 20 fps 缓慢变化。
翻转图像先缓存，波纹绘制使用水平图像条带，窗口尺寸或封面变化时更新缓存。
倒影与封面共用播放/暂停的整体缩放，页面不可见或离场时停止倒影刷新。

## 歌词效果与浏览焦点

自动播放时，播放行作为视觉焦点，中心停在歌词视口高度的约 42%。
滚动曲线对齐 LyciaMusic 使用的 AMLL（2026-10-24）：每句独立解析式弹簧落位，
从视口顶部向下按 50 ms 的基础延迟逐句错峰，当前句以下每句把基础延迟除以 1.05；
换目标时按当前速度接续，不越过目标回弹，也不会顿一下再走。
当前行与未唱行保持相同字号，通过亮度、远景模糊和视口边缘渐隐区分状态，不再在高亮切换时缩放整行。
字号、对齐、高亮色与行距由歌词页外观面板配置（见 [`lyrics-appearance.md`](lyrics-appearance.md)），
字号固定 DIP（24–80），不再随窗口缩放。

未唱、悬停与逐字高亮共用同一份整行字形遮罩、DPI 和原点；各状态先合成为相同的位图，再移动到窗口坐标。
逐字高亮只更新颜色纹理，通过渐变画刷连续推进到字形内部。文本按 Unicode 文本元素拆分，音节进度按实际字形宽度分配，
组合字符和代理对不会被当作两个独立字形。逐行歌词仅高亮当前行，不把整句当成长音。

持续至少 1 秒的逐字音节保留发光，并随进度放大、上浮后落回原位；普通字不动。
长音字用独立排版绘制，绘制前先从主颜色纹理中挖掉对应字形，避免原位留下重影。

译文行没有自己的逐字时间（音节全是 `<0,0>`），因此跟随所属原文的演唱窗口
（原文行首到最后一个音节结束），按译文自身的字形宽度从左到右连续扫色：
与原文同时开始、唱完时填满，不会因为译文行的行首时间晚于原文而一直保持暗色，
也不会被误认成下一句。译文与原文仍属于同一个滚动单元。
同一播放段内，已经点亮的部分保持点亮；播放时钟的小幅向后校正不能让高亮收回或让当前行反复切换。
明确跳转或切歌时重新计算高亮；长音的渐变坐标与其实际绘制位置保持一致。

**浏览行与播放行是两个概念。** 滚动浏览时，位于显示锚点附近的歌词成为清晰的浏览焦点，
模糊距离围绕浏览行计算。鼠标悬停的句子也会清晰显示，方便选句。
浏览不会改变播放位置；点击一句后才按该句时间轴跳转。
不能继续围绕离开视口的播放行计算模糊，否则滑远后所有可见歌词都会模糊。

**选中底只跟鼠标（2026-10-23，2026-10-24 改为按句）。** 鼠标划过的行所在的**整个滚动单元**
铺一层圆角底：`#1AFFFFFF`、圆角 6，与侧栏选中底同色，横向占满歌词列，
纵向覆盖原文与译文两行加半个行距，不再只包住划到的那一行。
浏览时没有固定焦点行，只有鼠标划过的句子有底；非浏览时播放中的那一句本身已有逐字扫色，
不再叠底，悬停其他句子仍会显示这层底。

`CompositionDrawingSurface`，像素格式为 `B8G8R8A8UIntNormalized`，使用预乘透明度。
在 `CompositionTarget.Rendering` 中直接绘制并提交，避免额外的 `CanvasControl.Invalidate` 调度。
表面按 `XamlRoot.RasterizationScale` 换算物理像素，DPI 或视口变化时调整尺寸。

原有 `LyricsPlaybackClock` 继续把播放引擎约 5 Hz 的上报插值成连续时间。
普通上报从当前已显示的位置接续，小偏差以有限的速度调整逐步消化，不在上报瞬间改写位置。

## 快节奏高亮的推进连续性修复

原时钟在每次上报时，将位置立即改为“原锚点预测 + 音频偏差”，随后再把偏差逐渐消除。
音频上报晚于预测时，时间立即回退；渲染器的“不准收回已唱高亮”保护把这个回退截住，
于是高亮先停在原处，再等待时钟追上。正偏差则会立即向前跳。
这个过程约每 200 ms 重复，即使绘制按 60 fps 更新仍然出现，短音节和快节奏更加明显。

修复后，小幅音频校正保持上报瞬间的位置不变，从当前已显示的位置建立新锚点，
把剩余偏差逐步加入后续时间推进。校正期间速度限制在正常速度的 75%–125%，
校正窗口最短 200 ms；偏差较大时延长窗口，防止减速到零或向前猛跳。
下一次上报从包含已完成校正的位置接续，剩余误差重新计算，不能丢弃后回到旧预测线。
暂停冻结当前输出，恢复从冻结位置继续；明确跳转和超过 400 ms 的偏差仍立即对齐。
锚点和校正数据一次性发布，读侧不再分开读取可能不同步的位置与校正字段。

这一轮只修复时间推进，保留单向高亮保护、逐字渐变、长音和弹簧设置，没有调整帧率或效果强度。
新增 13 个确定性回归用例，其中 10 个在旧实现上失败；修复后全部通过。
快节奏用例按 60 fps 读取时间，每 200 ms 注入一次上报，覆盖 30、80、250 ms 延迟及抖动，
并用 80 ms 音节检查逐帧前进、换字连续和无回退。该验证用于复现推进错误，不等同于所有歌曲的帧率保证。

## 2026-10-05 歌词抖动复盘与最终验收

**状态：用户确认当前版本不再抖动，并要求记录原因、提交。** 前几轮的测试通过记录只代表各自检查过的路径，

### 为什么之前修好，后来又出现

共同原因是：**同一句歌词的可视位置由播放时钟、行滚动、整行缩放、长音变换和图层切换共同决定，
前一次修复与验证只覆盖了其中一部分。** 之后改变绘图路径时，没有同时保持所有状态下的基线、DPI 和字形像素一致，
又引入了新的视觉差异。

之前的播放时钟修复是真实有效的，它阻止正常校正让时间瞬间回退或前跳。这项保护一直保留。
但时间单向前进只约束「唱到了哪里」，滚动和绘制仍可改变「这句话画在哪里」。
因此用户都描述为“抖动”的现象，实际可能发生在不同层，不能用一次时钟测试或一次静止截图概括。

### 已证实的原因与证据

| 路径 | 本轮证实的问题 | 证据与最终处理 |
| --- | --- | --- |
| 行滚动 | 阻尼小于 1 的弹簧会越过目标后回弹，换目标时旧速度可能继续推向原方向 | 第一轮 9 个正式动画器用例中 7 个失败；改为临界阻尼并限制反向或过大的惯性 |
| 待高亮行 | 第一轮只修当前焦点，待高亮和移出的行仍走旧弹簧 | 后补 3 组非焦点行用例均复现越过目标；所有行改为单向收敛，保留错峰起步 |
| 字形变换 | 未唱到当前行有 0.92 → 1 的整行缩放；长音还有按进度变化的上浮和缩放 | 整行缩放统一为 1；长音按进度缩放/上浮、唱完落回原位（2026-10-31 恢复）；保留亮度、模糊、逐字高亮和发光 |
| 图层切换 | 未唱命令列表与活动行使用不同栅格化／采样路径，切换后轮廓像素不一致 | 125% DPI、相同颜色和固定位置的对照出现 alpha 35 → 63；未唱、悬停和高亮统一字形遮罩、位图原点及 DPI |
| 合成尺寸 | 绘图表面向物理像素取整，视觉仍按未取整尺寸铺满，产生微量缩放 | 合成视觉与绘图表面使用相同的物理像素尺寸 |

这些是代码和回归中各自证实的问题。最后的用户验收确认了组合修复的实际结果，
并不意味着可以把用户每一时刻的抖动都归因于表中某一个因素。

### 修复中引入的高亮回归

缓存字形后又出现“高亮只能扫到字体底部”。这是新绘制路径引入的回归：
固定行距没有指定 `LineSpacingBaseline`，字符行框从 Y=0 开始，实际文字却画在约 -34 DIP 的位置。
颜色纹理按字符区域填充，漏掉了上部。主行和长音子排版现明确使用行距 80% 的基线，

修复前的换行样例有 **7035 / 18785** 个实心字形像素未达到已唱亮度。修复后，

第一字唱完时顶部和底部均高亮，后续换行的未唱文字没有被串色。

### 识别判据

`BodianLyricParser` 在所有行折成 `raw` 之后、算 `Duration` 之前插了一个标记 pass：

- 按**行首时间戳完全相同的连续行**分组；
- 组内**同时存在**「有真实逐字时间」与「没有真实逐字时间」两种时，把没有的那些标为译文；
- **文件末尾单独补一条**：末组全无逐字时间、上一组有逐字时间、且末组里有非空文本时，
  把末组的非空行标为译文。末句译文没有「下一句」可借时间戳，会独自成组，同组配对认不出来；
  「上一组有逐字时间」同时排除了逐行版，那里每组都没有逐字时间，不会误标；
- 其余情况一律不标。

「有真实逐字时间」看的是音节**时长**而不是有没有标签：译文行的 `<0,0>` 会解出零时长音节，
空行则一个标签都没有 —— 两者都算「没有真实时间」，正好一起被划进译文那一侧。

判据**不看行的先后**（实测译文行排在原文之前，靠位置猜会猜反），也不加「长度 < 6 跳过」
之类的启发式。中文歌天然不受影响：时间戳唯一，根本不成组。

### 已知限制

**逐行版（`lrcx=0`）认不出译文。** 那份没有任何逐字标签，组内两行都「没有真实时间」，
判据分不出哪条是译文 —— 这时一律不标，开关点了没反应。
宁可如此，也不能误删真歌词。当前实现只在「有逐字轨但返回空串」时才退到 `lrcx=0`，命中面小。

判据本身的实测样本是 Lemon（`rid=40602735`）、See You Again（`rid=6340467`）与
Shape Of You（`rid=21141302`），不是协议保证；后两首的结尾都是「末句译文 + 同时间戳空行」。
遇到「真歌词被当成译文删掉」的反例时，第一处置手段就是让用户把这颗开关关掉 ——
译文行留在文档里，关掉即恢复。

### 剔除而不是跳过

「不显示译文」是把行**从文档里剔掉**（`LyricDocument.WithoutTranslations`），
不是让渲染层逐行跳过 —— 后者会让行高与滚动位置跟着错。

剔除**不重算 `Duration`**：成对两行行首相同，剔掉其中一条既不改变另一条的 `Start`，
也不改变「下一行行首 − 本行行首」。副作用是好的：此前配对里的第一条 `Duration` 推出来是 0、
会退回 5 秒兜底，两条窗口互相重叠；现在不再有这一层。

渲染层的大部分（逐字扫光、长音、遮罩）**一行都没改** —— 它只认 `LyricDocument`，
开关改的是这个文档本身，换文档即换画面。滚动动画是例外，见下一节。

### 空行不占位（2026-10-24）

歌词内容里的空白行（译文占位、段落分隔、结尾空行）没有可显示的文字，此前会占掉一整行，
界面上表现为凭空空一行。现在 `LyricsViewModel.SyncDocument` 投影前先调
`LyricDocument.WithoutBlankLines()`，把无文字的行整行剔掉，无论它有没有被标成译文。

剔除同样**不重算 `Start` / `Duration`**：非空行自己的时间窗不变；原来的空行时段里
`IndexOfLineAt` 会继续返回上一句，比高亮消失更自然。

### 双行歌词的滚动：按句对齐锚点 + AMLL 弹簧（2026-10-23 ~ 10-24）

双行歌词（原文 + 译文）在文档里是「原文 / 译文 / 原文 / 译文…」。此前每行各自成滚动单位，
译文比原文晚 35 ms 起步，滚动中两行会拉开；相邻句隔两行，错峰延迟翻倍，邻句明显落队。
现在分两层处理：

| 层 | 变化 |
| --- | --- |
| 单元 | `LyricDocument.BuildScrollUnitMap` 把一句原文与其紧邻译文归为一个单元（译文并入上一句；文件开头的译文并入后面的第一句；剔除译文后每行自成单元），单元内各行共用同一个弹簧位置 |
| 锚点 | 取单元的文档空间中心（`LyricsLayoutSnapshot.UnitCenters`），双行绕 42% 焦点线上下居中；浏览边界同样按首 / 末单元中心 |
| 弹簧 | `LyricSpring` 按 AMLL 的纵向弹簧参数（mass 0.9 / damping 15 / stiffness 90）做解析求解，约 0.5 秒软落位、过冲不到 1%；换目标时按当前位置和速度重新起算 |
| 错峰 | 对齐 AMLL：基础延迟 50 ms 从视口顶部向下逐句累加，当前句及以下每句把基础延迟除以 1.05；浏览时关闭错峰，整块跟手 |

曲线来源是 LyciaMusic 使用的 AMLL（`@applemusic-like-lyrics/core` 0.2.0），求解器源自
pushkine 的 MIT 实现。单行歌词（含关闭译文、中文歌）的单元就是行本身，行为与上一版一致。
回归见 `LyricTranslationTests` 的 `ScrollUnits_*`、`LyricSpringTests` 与
`LyricsScrollAnimatorTests`（单元同动、延迟起步、浏览跟手、落位停止）。

### 开关的落点

| 层 | 位置 |
| --- | --- |
| 偏好 | `Models/LyricsSettings.cs`（`ShowTranslation`，默认开） |
| 存储 | `JsonLyricsSettingsStore` → `%LOCALAPPDATA%\Bowen\lyrics.json`（PascalCase 属性名，与其它设置一致） |
| 生效 | `LyricsViewModel.ShowTranslation`：构造时同步读出（避免首帧闪一下），改动即落盘并重投影 `Document` |
| 可用性 | `LyricDocument.HasTranslation` → `LyricsViewModel.HasTranslation`：**必须在未过滤的 `_fullDocument` 上算**，投影后的 `Document` 上永远是 `false` |
| 界面 | `LyricsPage` 顶栏那颗按钮：`IsEnabled` 绑 `HasTranslation`；开/关只差图标不透明度；提示文案三种（显示译文／关闭译文／这首歌没有译文） |

**默认开**：译文本来就在内容里、客户端此前一直显示，这个开关只是给用户一个关掉的办法，
不是新增一种显示。所以默认行为与加开关之前完全一致。

回归：`LyricTranslationTests`（标记、顺序颠倒、空行成组、三行一组、重复时间戳不误标、
逐行版不标、中文歌不标、`HasTranslation` 四种情形、剔除后 `Start`/`Duration`/`IndexOfLineAt` 不变）
与 `LyricsSettingsStoreTests`。

## 恢复态进歌词页：直接定位到续播位置（2026-10-24）

重启后恢复出来的曲目只铺到播放条，引擎里没有加载文件，`IPlaybackService.Position` 是 0。
此前歌词页、桌面歌词和小窗三个渲染器都直接拿这个 0 去对时钟，进页停在第一句，
而播放条上的进度明明是上次停下的位置。

现在起点统一取 `LyricsViewModel.TimelinePosition`：引擎处于 `Idle` / `Stopped` 时用
`PlaybackCoordinator.RestoredState.Position`，真正起播后一律读引擎。三处消费方：

| 消费方 | 位置 |
| --- | --- |
| 沉浸歌词页 | `LyricsCanvasView.OnLoaded` 用它 `Sync(force: true)` |
| 桌面歌词 | `DesktopLyricsCanvasView.OnLoaded` |
| 小窗歌词行 | `MiniPlayerWindow.ResumeVisualUpdates` |

`LyricsViewModel` 自己的当前行（`CurrentIndex` / `CurrentLineText`）也在 `RefreshAsync` 与
`SyncDocument` 里改用同一入口，小窗那行不会和主歌词页对不上。

**不自动播放**：进页只是对齐到那一句，按播放仍从保存的位置续播。
**起播后 `RestoredState` 置空**（`PlaybackCoordinator.StartAsync`），它只表示「还没开播的续播目标」；
再留着它，放完之后引擎闲置时又会按旧位置对齐。

验收：重启停在约 1:30 → 不点播放直接点封面 → 歌词页居中在 1:30 那一句、进度条也是 1:30；
桌面歌词 / 小窗同样；按播放从 1:30 续播。
