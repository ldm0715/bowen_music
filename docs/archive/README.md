# 归档

**这里的文件写完就不改。** 每完成一个阶段往这里放一份，记录当时**解决了什么、怎么解决的、踩过什么**。

## 和活文档的分工

| 目录 / 文件 | 性质 | 用法 |
| --- | --- | --- |
| `docs/backlog.md` | **活** | 未完成事项清单。每次开工先看它 |
| `docs/roadmap.md` | **活** | 阶段划分与进度 |
| `docs/bodian-api-reference.md` | **活** | 协议主文档，结论随实测更新 |
| `docs/tech-stack.md` / `lyrics-ui.md` | **活** | 选型与方案，结论随实现修正 |
| **`docs/archive/`** | **冻结** | 阶段回顾与经验教训。**不要在这里补更新** —— 有变化写进活文档，再开一份新的归档 |

## 为什么要有它

活文档只保留**当前正确**的结论：协议会变、方案会改、被推翻的判断会被直接删掉。
但「当时为什么这么判断、后来怎么发现是错的」这种信息在活文档里存不下，而它恰恰是避免重走弯路的东西 ——
比如「某条规则照搬参考实现会删掉真实歌词」这种教训，只写在代码注释里，下一个读到的人未必会看到。
