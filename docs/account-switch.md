# 账号快捷切换

> **状态：已实现。** 2026-10-08 提出，同日落地。
> 起因：账号面板里只有「退出登录」，想换回另一个账号就得重新扫码/发短信。
>
> 实现与本文有一处差异，是铺到代码里才看清的：
> **「刚刚发生过切换」这个短时标记不需要了。** 原设计想用它区分「本来就没登录」与
> 「刚切过去就失效了」，但 <c>BodianSession.Cleared</c> 的事件参数本来就能区分 ——
> 服务端判死（11012）与本地登出是两条不同的路径，给参数加一个 `ServerInitiated` 布尔即可，
> 而且它的语义比「刚切过」更准：**会话在使用的过程中被服务端判死，提示同样是对的**，
> 不必只覆盖「刚切换」那一种。

## 问题

应用支持登出后用另一个账号登入，但**换号的代价是完整的重新认证**：
扫码或手机号验证码。常用两个账号的人每次都要走一遍。

而这件事的**另一半已经不用做了**：2026-10-08 落地的多账号数据作用域
（见 [`multi-account.md`](multi-account.md)）已经让「切号后队列 / 最近播放 / 搜索历史跟着换」
这条链子通了 —— `BodianSession.Set` 触发 `Changed`，队列协调器、搜索页、存储页各自跟上。

所以本设计只需要解决两件事：**把凭据记住多份** + **给一个入口**。

## 一、为什么切换不需要重新认证

`BodianLogin.TryRestorePersistedSession()` 已经把整条路走通了：

```
读凭据 → session.Set(uid, token) → 用凭据里的昵称/头像/会员快照建 Account → RaiseAccountChanged()
```

**这一路不联网、不校验身份**。切到另一个账号就是喂给它另一份凭据，之后 `Changed` 的连锁反应与
「启动时恢复会话」完全同一条路径。干净、便宜，没有新的时序问题。

代价是：那份 token 可能已经在服务端失效（很久没登、或在别处登出过）。见第三节。

## 二、凭据清单存哪

### 不能改 `session.dat`

它只有**一份**，是「当前会话」；而且：

- **与 P0 探针共用**（`tools/Bodian.Probe` 有自己的同名实现）；
- **JSON 字段名是对外契约** —— `ICredentialStore` 的 remarks 写着「改动这几个名字等于改凭据文件格式」；
- DPAPI 的 entropy `Bodian.Session.v1` 也必须与探针一致。

往里塞一个数组会同时破坏这三点。所以**新增一份**。

### 新文件：`remembered-accounts.dat`

| 项 | 选择 | 理由 |
| --- | --- | --- |
| 位置 | `%LOCALAPPDATA%\Bowen\remembered-accounts.dat`（根目录） | 它是**跨账号**的索引，不能放进 `accounts\<uid>\` 里（那是按账号分的数据目录）。 |
| 名字 | `remembered-accounts.dat`，**不叫 `accounts.dat` / `sessions.dat`** | 目录里已经有一个 `accounts\`；而 `session.dat` 与 `sessions.dat` 只差一个字母，凌晨两点排查时必然看错。 |
| 加密 | DPAPI `CurrentUser`，**entropy 用 `Bodian.Accounts.v1`**（与 session 的 v1 不同） | 里面是**可用的 token**，与 `session.dat` 同级敏感。entropy 分开是为了防「把这份 blob 改名成 `session.dat` 也能解开」——两个文件的保护域不该可互换。 |
| 内容 | `{ "Accounts": [ { "Credential": {...}, "LastUsedAt": "..." } ] }` | **复用 `BodianCredential`**，不照抄一遍字段。上次加 `VipBadge` 时吃过亏：同样的字段在两处各写一份，加字段就得记得改两处。 |
| 上限 | 5 个，超出丢最久未用的 | 一份能直接登进账号的 token 清单，无上限只是白担风险；界面上也放不下。 |
| 读失败 | 当空清单，**不删文件** | 与其它 store 一致：宁可列表空着，也不让应用起不来，更不替用户做删除决定。`session.dat` 仍然保证当前会话还在。 |
| 排序 | `LastUsedAt` 倒序 | 「最可能想切回去的那个」排最前。 |

## 三、token 失效怎么表现

**乐观切换**：直接切，不先发请求验证。失效时第一个业务请求会拿到 `11012`，
现有机制（`BodianSession.NotifyUnauthorized` → `Cleared` → `BodianLogin.OnSessionCleared`）
会把会话清掉并回到登录页。

补两件事，否则体验是「切过去就被踢，不知道为什么」：

1. **一条提示**：`11012` 把人踢回登录页时弹「该账号的登录已失效，请重新登录」。
   判据是 `BodianSessionClearedEventArgs.ServerInitiated`（不是比对文案 —— 拿中文串做分支，
   改一次措辞就断一次），本地主动登出不会弹。
2. **列表上标出来**：被服务端判死过的账号，在那次会话内显示为「登录已失效」。
   **只在内存里标，不落盘** —— 失效是服务端当下的态度，本机没资格记成永久结论；
   同一个 uid 重新登录拿到新 token 时清掉，或该账号被「移除」时清掉。

不做「切之前先验证」的理由：多一次往返与等待，而它挡掉的那个场景（切到一个失效账号）
本来就少见；真发生了，一次提示 + 一次重新登录即可恢复。

## 四、界面

账号面板（`MainWindow.xaml` 的账号 `Flyout`）里，在「退出登录」上方加一个
**「切换账号」**按钮，点开进入**二级列表**。

```
┌ 账号面板（一级）─────────┐        ┌ 切换账号（二级）─────────┐
│  [头像]  昵称 / 会员标    │        │  ← 切换账号              │
│  关注歌手  听歌时长      │  点 →   │  ✓ [头像] 昵称 A         │
│                          │        │    [头像] 昵称 B  ⋯移除   │
│  [    切换账号    ]      │        │  ──────────────────      │
│  [    退出登录    ]      │        │  [   ＋ 添加账号   ]     │
└──────────────────────────┘        └──────────────────────────┘
```

- **二级列表做在同一个 `Flyout` 内**（两块 `StackPanel` 切 `Visibility`），不新开一个 `Flyout`。
  `Flyout` 套 `Flyout` 在 WinUI 里行为很难收拾；`ContentDialog` 对「点一下就切」这种
  「快捷」动作又太重。
- **当前账号打勾且不可点**，避免「切到自己」这种空操作。
- **「移除」要确认**，与「取消收藏」那套一致；确认文案里写明**只移除登录凭据、不动本地数据**
  （见第六节）。
- **「添加账号」= 登出到登录页**（登出会保留清单，见第五节），登录成功后自动记进清单。
  它和「切换账号」是两件事，所以分开放。
- 每次打开二级列表时刷新一次（`OnAccountFlyoutOpening` 已有钩子），并顺手把当前账号的
  `LastUsedAt` 推上去。

## 五、「登出」的含义要改

**登出只清当前会话与 `session.dat`，清单里的凭据留着** —— 否则「快捷切换」就退化成
每次都要重新扫码，「记住」也就没意义了。

直接后果，必须写进文档也写进 UI 文案：

> **「登出」不再等于「把凭据从这台机器上删掉」。** 想真正清干净，要逐条「移除账号」。

所以「退出登录」按钮的 tooltip 要从现在的
「清除本机保存的会话，回到扫码登录」改成
「清除当前会话，回到登录页；已记住的账号仍在列表里」。

## 六、与既有设计的关系

| 关注点 | 结论 |
| --- | --- |
| `session.dat` / 探针 | **一行不改**。新文件独立，探针不受影响。 |
| 未登录时也能选账号 | **账号弹层在未登录时直接就是账号列表**（没有账号卡片可看，而刚登出的人最想做的就是换个账号回来）。第一版把列表放在「已登录」那一屏里，于是「登出保留清单」在界面上等于白留 —— 用户退出登录后根本找不到切回的入口，只能重新扫码。标题、底部按钮名（未登录叫「登录」、已登录叫「添加账号」）、空态文案都随登录态变。 |
| 登出后列表里的选中态 | **没有任何一行该是选中的**（`Account` 已是 null，谁都不是「当前账号」）。列表的行是「打开弹层那一刻」建的快照，「谁是当前账号」不跟着会话自己变 —— 所以账号变更时要重建列表，否则那一行会一直亮着底色、还点不动。 |
| 数据隔离 | 已就绪，无需改动。切号即触发 `PlaybackCoordinator` 换队列（并弹「播放队列已切换」）、搜索页重载历史、存储页换作用域。 |
| 切号后页面要重拉 | **两条路，缺一不可**：① 当前那一页还在屏幕上、不会再走一次进场，由 `IAccountScopedView` 通知外壳叫它重拉；② 离开再回来会复用旧页面实例（导航栈与闲置页面缓存持有它），由 `PagedList<T>` / `PlaylistTracksViewModel` 的「已加载」守卫判「**为哪个账号**加载过」来自动重拉。只做 ① 的话，切号后点侧栏「收藏的歌单」看到的还是上一个人的 —— 这个缺口实际发生过，见 `f823ba7`。 |
| `IBodianLogin` 的契约注释 | 现在写着「`CompleteAsync` 与 `LoginByPhoneAsync` 是仅有的两个会改动会话的入口」，加切换后要改成三个。 |
| 列表与 `session.dat` 漂移 | 探针登录只写 `session.dat`、不写清单。应用启动时若发现当前会话的 uid 不在清单里，**补记进去**（自愈），免得「明明登录着却不在列表里」。 |
| 移除账号 vs 删数据 | **只删凭据，不动 `accounts\<uid>\`。** 「移除登录」和「删掉我的播放记录」是两件事，捆在一起会让用户不敢点。代价是会留下没有凭据的孤儿数据目录 —— 记在 backlog，将来在存储页加一项「其他账号」来清。 |

## 七、开放问题

| # | 问题 | 当前倾向 |
| --- | --- | --- |
| 1 | 清单上限 5 个够吗 | 够。超出按最久未用淘汰，并在列表底部提示已被淘汰过 |
| 2 | 切号后要不要停掉正在播的歌 | **要**，且复用现成行为（切作用域已经会停播 + 提示），不需要新代码 |
| 3 | 设置页要不要也放一份 | 不。账号属于标题栏，设置页再放一份只会多一个要同步的地方 |
| 4 | 多设备上同一账号 | 不在本次范围（`devid.txt` 是设备级的，换机器本来就是新设备） |

## 八、验收清单（实现后）

1. 登录 A → 面板「添加账号」→ 登录 B → 二级列表里 A 与 B 都在，B 打勾。
2. 点 A → **不重新认证**，头像/昵称/会员标立刻换成 A；标题栏、侧栏跟着换。
3. 切回 A 后：队列、最近播放、搜索历史都是 A 自己那份（B 的不串进来）。
4. 切号时正在播 → 停播 + 一条「播放队列已切换」。
5. 「退出登录」→ 清单里 A、B 都还在 → 能直接切回任意一个。
6. 「移除」B → 确认后 B 从列表消失；`accounts\<B 的 uid>\` **仍在磁盘上**。
7. 手工把 B 的 token 改成无效值 → 切到 B → 回到登录页并提示「该账号的登录已失效」；
   该次会话内 B 在列表上标为失效。
8. `devid.txt` 与 `session.dat` 的格式/内容语义**均未改变**（探针仍能读）。
9. 清单文件是 DPAPI 密文：`strings` 之类看不到 uid 与 token 明文。
