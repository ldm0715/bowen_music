# 歌词海报（分享卡片）

**状态：2026-11-04 设计稿 v5，初版已实现。**

首版收敛为单模板：固定白底、1080 宽、高度随歌词内容自适应、选中行数不限。已定入口、0 行不可生成；照片卡与背景继承推迟到后续。

## 0.1 初版修订（2026-11-04）

按首轮试用反馈调整，以下四条覆盖下文对应设计：

- 选择粒度改为**行**：原文与译文各自是独立选择项，**不设行数上限**，海报高度随选中内容增长。
- 打开选择面板时滚动到当前播放行，但**不默认勾选**。
- 画布宽度按内容收缩（780–960），高度自适应（最小 720，上限 16000），长句折行计入总高。
- 二维码边长 96（应用图标 48 的两倍）；歌名 / 歌手 28 / 22，超长显示省略号；品牌文字顶部与歌名齐平。
- 封面与歌词字号都随选中行数自适应：行少时封面更大（最大 560）、字号更大；行多时共同收缩。
- 封面、歌词、品牌共用同一条左边线（108），不做水平居中。
- 歌词左对齐、固定左右边距 108；字号 42–46，行距 1.8 倍，低于 42 不再缩字，放不下就折行。
- 译文与原文使用完全相同的字号、行距和颜色，不单独缩小或压暗。
- 页脚歌名 / 歌手与二维码按可见墨迹垂直居中，两者之间有一条浅灰竖线。
- 选句头部：计数「已选 n 行」在左，全选 / 清空在右；底部次按钮为「复制歌词」（仅复制所选，未选时禁用），关闭走标题栏 X。

## 0.2 海报自定义（v5）

预览阶段改为「左侧预览 + 右侧设置」，任一设置变化立即重渲染；保存 / 复制只认最新一次成功渲染的 PNG。预览阶段内容约 560 宽：预览卡 240、设置列 300，设置直接铺在对话框背景上。

| 项目 | 规则 |
| --- | --- |
| 字体 | 系统全部字体，复用 `FontSettingsViewModel.Fonts` 与 `FontPicker`；**只作用于歌词**，歌名 / 歌手 / 品牌字标保持 `Microsoft YaHei UI` |
| 背景 | 纯色；自动 = 封面主色经 `ColorPalette.SolidBackground(seeds, Dark)` 压暗；预设 = 8 个深色 + 白 / 暖白；另可色轮自定义 |
| 文字颜色 | 自动（背景亮度 > 0.45 用 `#1A1A1A`，否则白色）、白、黑、7 个高亮色、色轮自定义 |
| 品牌 logo | 深色背景用 `RippleLight.png`，浅色背景用 `Ripple.png`，不单独提供开关 |
| 二维码 | 始终画在 112px 白色圆角托板上，码元保持黑色；深色背景也能扫 |
| 派生色 | 歌手 = 文字色 60% alpha；竖线 = 15%；封面缺失占位 = 7% |
| 色轮 | 海报对话框本身是 `ContentDialog`，不能再叠 `ColorPickerDialog`；色盘拆成 `ColorPickerPanel`，用 `ColorPickerFlyout` 承载 |
| 持久化 | 独立 `lyrics-poster.json`，字段见 `LyricPosterSettings`；字体与文字/背景颜色跨会话记住 |
| 预览大图 | 点击预览图打开 `CommentImageViewer` 覆盖层；按海报宽高比和窗口高度扩成竖版查看器，不拉满窗口宽度。支持缩放 / 平移 / Esc 关闭。复用评论区查看逻辑，仅新增按 `ImageSource` 直接显示内存 PNG 的入口 |

## 0. 目标

把歌词做成一张可以直接发出去的图片。首版产物包含：

- 专辑封面、歌名、歌手
- 用户勾选的歌词，最多 8 句
- 分享链接二维码
- 应用品牌区

首版不做背景图、不做整首长图、不做模板切换。先把「选词 → 出图 → 发出去」这条主路径跑通。

## 1. 入口与流程

```
分享按钮（单击）
   └─ 上浮面板
        ├─ 复制分享链接        （沿用现有行为）
        └─ 制作歌词海报
             └─ 歌词选择面板
                  ├─ 未勾选任何歌词 → 「生成海报」禁用
                  ├─ 勾选 1–8 句   → 「生成海报」可用
                  └─ 已达 8 句     → 其余行不可再勾选
                       └─ 海报预览
                            ├─ 保存图片
                            ├─ 复制图片
                            └─ 返回修改
```

| 项目 | 行为 |
| --- | --- |
| 触发 | 歌词页左下角现有的分享按钮，**单击**后向上弹出面板 |
| 面板位置 | `Placement="Top"`，锚在按钮上方 |
| 面板内容 | 两行，整行可点：「复制分享链接」和「制作歌词海报」 |
| 悬停 | 不作为主触发方式。首版只做点击；后续若要加悬停加速，照 `VolumeButton` 的延迟规则实现，点击路径必须保留 |
| 无歌词时 | 分享按钮仍可用；「制作歌词海报」整行置灰，副标题写「当前歌曲没有歌词」 |
| 其他页面 | 播放条、专辑、歌手、歌单页的分享按钮保持一键复制链接，不改成菜单 |

面板是自定义内容的 `Flyout`，不是 `MenuFlyout`：每行需要图标、标题和一行说明。底色复用 `BowenAcrylicBrush`，圆角 8，与 `MoreFlyout` 一致。

### 实现注意

1. `ShareButton` 目前是 `Command="{x:Bind Player.ShareCommand}"`（`LyricsPage.xaml:346`）。挂了 Flyout 后点击会同时执行 Command，必须在改成面板入口时去掉这个绑定，把复制动作移到面板第一行。
2. Flyout 是 popup，不受 `SetChromeVisibility` 管。必须增加 `_shareFlyoutOpen`，并计入 `ScheduleChromeHide` 与 `HideChrome` 的守卫（现有 `_moreFlyoutOpen` 的处理见 `LyricsPage.xaml.cs:943` 附近的注释），否则面板还开着、底部控制台已经淡出。
3. 弹层跟随主窗口主题，复用 `ApplyFlyoutTheme` / `PopupTheme.Apply`，不要继承歌词页固定的深色。
4. 不要把这两个选项塞进 `TrackActionsMenu`。它是跨页面复用的曲目操作菜单，分享格式是歌词页专属。

## 2. 歌词选择面板

宽版 `ContentDialog`，`BackgroundCropDialog` 已有「大预览 + 操作」的先例。

| 区域 | 内容 |
| --- | --- |
| 顶部 | 歌名 + 歌手，作为上下文 |
| 列表 | 按句显示，每行一个 `CheckBox`；译文作为同一行的次要文字，不单独占一行 |
| 计数 | 「已选 3 / 8」实时更新 |
| 操作 | 全选（最多选前 8 句）、清空 |
| 底部 | 「生成海报」「取消」 |

规则：

- **默认勾选当前播放句**，让用户一进来就有内容可生成。
- **已选 0 句时，「生成海报」禁用**，并在按钮旁提示「至少选择 1 句歌词」。
- **上限 8 句**。达到 8 句后其余行置灰，不能再勾选；「全选」只选前 8 句，并提示「最多 8 句，已选前 8 句」。
- 列表按**句**组织，不是按裸行。`LyricDocument.Lines` 里混着译文行（`LyricLine.IsTranslation`），原文与紧跟的译文要归成一组；勾选一句时整组进入海报，译文是否输出由译文开关决定。
- 空行在列表里不显示，也不计入 8 句。
- 当前歌曲没有歌词时正常到不了这里；对话框仍要有空状态兜底，并把「生成海报」禁用。

## 3. 海报预览

点击「生成海报」后进入预览，展示实际渲染结果。

| 项目 | 行为 |
| --- | --- |
| 预览 | 与导出共用同一个渲染器，按比例缩小显示，所见即所得 |
| 保存图片 | `FileSavePicker` 选位置，导出 PNG |
| 复制图片 | 剪贴板同时写入 PNG 与文本；文本取分享链接 |
| 返回修改 | 回到歌词选择面板，保留原有勾选 |
| 上报 | 第一次成功保存或复制时调用一次 `Statistics.ReportShareAsync`；同一会话重复导出不重复上报 |

## 4. 海报版式（首版固定白底）

固定 **1080 × 1920**（9:16），白色背景。首版不做自适应高度，8 句歌词在 9:16 内排得下；这样也避免长图高度计算带来的复杂度。

### 信息层级

自上而下：

1. 专辑封面：240 × 240，圆角 16，居中放置
2. 歌词：左对齐，最多 8 句
3. 底部左侧：应用图标 + 「波纹音乐」文字标
4. 底部右侧：歌名（粗）、歌手（次）、二维码，整体右对齐

不显示时长、音质、点赞数、评论数这类调试性质的信息。

### 版权行

QQ 海报顶部有 `OP / SP`，本项目**没有这份数据**：

- `Track` 只有 `Title`、`ArtistText`、`AlbumName`、`CoverImage` 等字段。
- 歌词接口不返回词曲作者或版权方；`BodianLyricParser` 只处理带时间戳的行。
- 因此首版不显示 OP/SP，也不显示「作词 / 作曲」，不伪造。
- 歌词正文里如果本来就有带时间戳的 `词：xxx` 行，按普通歌词显示，这是解析器的既有约定，卡片不为它开特例。

### 排版参数（1080 宽基准）

| 项目 | 数值 |
| --- | --- |
| 画布 | 1080 × 1920 |
| 背景 | `#FFFFFF` |
| 左右边距 | 72 |
| 封面 | 240 × 240，圆角 16，上边距 96 |
| 歌词字号 / 行距 | 40 / 64 |
| 译文 | 30 / 44，颜色 `#666666`，紧跟在原文下一行 |
| 正文颜色 | `#1A1A1A` |
| 歌名 / 歌手 | 36 粗 / 26，`#666666` |
| 二维码 | 180 × 180，保留静区 |
| 底部安全区 | 72 |

- 字体使用卡片固定的一套排版字体，**不跟随歌词页的字体设置**；否则用户换成花体后，分享图会失控。
- 8 句原文加 8 行译文在 40 / 30 字号下仍能放进 1920；开启译文后如果实际排版溢出，先降到正文 36、译文 28，仍溢出则提示用户减少选择。
- 歌词从封面下方固定距离开始排，不垂直居中；少于 8 句时留白，底部品牌区始终贴底。

## 5. 歌词规则

- **选择粒度是「句」**：原文与紧跟的译文为一组，计数按句，不按裸行。
- 上限 8 句。达到上限后其余行置灰，不允许继续勾选。
- 0 句不能生成海报。
- 译文跟随歌词页的译文开关，默认关；开启后每句的译文排在原文下一行，样式见 §4。
- 逐字轨只取整行文本，不呈现逐字布局。
- 单行过长按宽度折行，不截断，不在词中间强制断行。
- 全部被剔除后没有可显示的行，按「无歌词」处理，禁止导出。

## 6. 分享链接二维码

项目已有 `QRCoder 1.8.0`（`Directory.Packages.props`），并由 `QrImageFactory` 用于登录二维码。**不新增依赖。**

| 项目 | 约定 |
| --- | --- |
| 内容 | 与「复制分享链接」完全一致：`ShareLinks.BuildTrackLink(musicId, uid)` |
| 纠错等级 | M，与登录二维码和探针一致，不为「少几个码元」降到 L |
| 渲染 | 只用库自带的 `PngByteQRCode` 渲染器。**不要自己遍历 `ModuleMatrix`**：行列读反会得到肉眼正常但扫不出来的转置码（`QrImageFactory.cs` 已记录这个坑） |
| 取像素 | 给 `QrImageFactory` 增加返回 PNG 字节的方法，供 Win2D 的 `CanvasBitmap.LoadAsync` 使用；不要为了卡片另写一套二维码生成 |
| 白底卡片 | 二维码直接放在白色画布上，保留静区，不需要额外托板；码元保持深色，不跟主题换色 |
| 缩放 | Win2D 用 `NearestNeighbor`，模块按整数像素对齐；线性插值会糊边 |
| 尺寸 | 180 × 180，每模块约 6 px |
| 失败 | 生成失败只记日志、不画二维码，卡片照常导出；右侧信息块重新排版 |
| 链接长度 | 曲目链接在 ECC M 下通常是版本 4–5，180 px 足够。以后扩展到歌单/专辑时，模块低于约 4 px 就放大二维码区域 |

二维码下方可加一行「扫码听歌」。链接里包含分享者 uid，这是现有分享链接的行为，提示文案里要说明。

## 7. 品牌与导出

### 品牌区

- 左下：应用图标 + 「波纹音乐」文字标。
- 右下：歌名、歌手、二维码。
- **不要写「AI 歌词海报」**。卡片不是 AIGC 生成的，写「歌词海报」或只写应用名。
- 现有 `Assets/Ripple.png` / `Ripple.ico` 只有图标，没有横版字标，实现前需要补一张 wordmark；这是前置资源。

### 导出

| 项目 | 约定 |
| --- | --- |
| 格式 | PNG，1080 × 1920 |
| 保存 | `FileSavePicker`；文件名 `歌手 - 歌名 歌词海报.png`，替换 Windows 非法字符 |
| 剪贴板 | 同时放 PNG 与文本；文本取分享链接 |
| 出图 | 用 Win2D `CanvasRenderTarget`，不用 `RenderTargetBitmap`（后者只能拿到显示分辨率，`ImageCropView` 已有同类结论） |
| 线程 | 生成在后台线程，导出期间按钮置 loading |
| 预览 | 与导出共用同一个渲染器，按比例缩小显示 |

### 隐私

- 二维码内容是公开分享链接，包含分享者 uid。
- 不上传歌词、封面或生成结果；海报完全在本地生成。

## 8. 失败降级

| 失败点 | 行为 |
| --- | --- |
| 封面加载失败 | 用灰色圆角占位块代替，歌词与底部照常排，不阻塞导出 |
| 二维码生成失败 | 不画二维码，歌名与歌手右对齐，不阻塞导出 |
| 字体缺失 | 回退系统字体，不更换版式 |

## 11. 实现拆分（建议）

| 部分 | 说明 |
| --- | --- |
| 分享面板 | `LyricsPage` 内新增 Flyout；`_shareFlyoutOpen` 接入 chrome 守卫 |
| 歌词选择面板 | 宽版 `ContentDialog`：按句分组、勾选、8 句上限、0 句禁用 |
| 海报预览 | 显示渲染结果；保存、复制、返回修改 |
| 卡片渲染器 | Win2D 离屏渲染 1080 × 1920；排版参数集中在一处 |
| 排版计算 | 行数、折行、译文位置、封面与底部布局做成纯逻辑，放可单测的类 |
| 二维码 | 扩 `QrImageFactory` 返回 PNG 字节；沿用 ECC M 与库渲染器 |
| 剪贴板 | 扩 `IClipboardService`，支持同时写 PNG 与文本 |
| 品牌资源 | 补横版 wordmark |

复用现有能力：`CoverArtUrl`、`CoverImageCache`、`QrImageFactory`、`AppDialogs`、`PopupTheme`、`ShareLinks`。
