# 首页背景模式与封面取色改进

**日期：2026-10-31。** 起因是 issue #3 的最新回复：用户要的三种背景模式是给**应用主页**的，
播放页背景他已满意；同时他指出首页背景颜色和封面“看不出关系”。本文给出背景模式下沉到外壳、
取色算法改进、以及 Mica 与亚克力联动三部分方案。

**实施状态（2026-10-31）：阶段 A（多色提取、OKLCH 主题映射）、阶段 B（外壳背景模式、
背板协调器、Mica、纯色）与阶段 C（自定义图片）已完成；阶段 D–E 未开始。**

相关：[`ambient-color.md`](ambient-color.md)（现有取色规则与实测）、
[`ui-refresh.md`](ui-refresh.md) §8（封面取色与层级分离）、
[`lyrics-appearance.md`](lyrics-appearance.md)（歌词页已实现的背景模式）、
[`performance.md`](performance.md)（取色与背景资源开销）。

---

## 1. 结论

1. 背景模式做在歌词页是落点错误。三种模式（Mica / 自定义图片 / 取色）要的是外壳背景，
   播放页保持现状。
2. 首页现在已经有封面取色（`AmbientBackdrop`），但“感觉没关系”不是取色失效：
   日志证明主色是正确的、多样的。问题在派生：**只取一个主色，再按 ±40° 派生三个同族色**，
   并且把饱和度、明度强制拉高，灰阶封面还会直接换成固定默认配色。
3. 改进分两步：先改取色（多色提取 + 保留原色明暗 + 灰阶不再跳默认），
   再把背景模式下沉到外壳（封面取色 / Mica / 自定义图片 / 纯色）。
4. Mica 与现有亚克力确实需要联动。Mica 是窗口级背板，现有亚克力刷的 tint 是按
   “深色实底或氛围渐变”调的；直接叠在 Mica 上会发浑或让卡片糊掉。方案是按背板模式切换亚克力档。

## 2. 目标与非目标

### 目标

- 外壳（所有常规页面）背景可在四种模式间互斥切换：封面取色、Mica、自定义图片、纯色。
- 封面取色让用户能直观看出颜色来自当前封面，而不是一套固定渐变。
- 自定义图片复用歌词页已有的选图、裁剪、暗度、模糊能力。
- 切换背景模式时，亚克力表面、外壳底色层、标题栏与侧栏的观感保持协调。
- 歌词页与 MV 沉浸页不受外壳背景影响，已有行为不变。

### 非目标

- 不改按钮、强调色、歌词文字颜色。动态取色仍然只作用于背景。
- 不做背景模式叠加（例如 Mica + 自定义图片）。
- 不引入网络壁纸、在线图库。
- 不改变歌词页现有背景功能的语义；只抽取共用代码，不重做视觉。

## 3. 现状

### 3.1 外壳背景层级

`MainWindow.xaml` 根 `Grid` 有三行（标题栏 / 内容 / 播放条），背景层跨三行：

| 层 | 元素 | 说明 |
| --- | --- | --- |
| 底色 | `ShellSurfaceBorder` | `AppSurfaceBrush`：浅色 `#FAFAFA`，深色 `#121212` |
| 氛围 | `ShellBackdrop`（`AmbientBackdrop`） | 384×256 预渲染 BGRA，整窗拉伸 |
| 内容 | `TitleBar` / `NavigationView` / 播放条 | 侧栏与内容区背景都被覆写成透明 |

- `AmbientBackdrop` 只在取色结果变化时重绘，静止时零刷新。
- 三团光晕位置固定（左上、右侧中部、底部中间），透明度从中心 208/255 递减到 0。
- 整层再乘 `AmbientOpacity`：浅色 `0.55`，深色 `0.62`。
- 沉浸态（歌词 / MV）时整组外壳元素隐藏，由沉浸页自己负责背景。

### 3.2 取色链路

```
PlayerViewModel.CurrentCoverUri / CurrentTrackId
  → CoverArtUrl.Jpeg(cover, 96)          改写成 96px JPEG
  → BitmapDecoder（CPU 像素）
  → ColorQuantizer.Dominant              分桶 + 两段式打分
  → ColorPalette.Ambient                 由单个主色派生三团
  → AmbientBackground.Render             预渲染光晕
```

`ColorQuantizer.Dominant` 已经是两段式：先筛面积、饱和度、亮度达标的彩色桶，
找不到再退回面积主色。本机日志显示主色确实多样（`#C78B67`、`#33558A`、`#79541A`、
`#3C211D`、`#888886`），近期没有解码失败。

### 3.3 为什么“感觉不到和封面的关系”

`ColorPalette.Ambient` 对主色的处理：

| 条件 | 处理 |
| --- | --- |
| 饱和度 `< 0.15` | 直接返回固定默认配色：青绿 `#18E0B6`、亮蓝 `#3790FF`、紫 `#A158FF` |
| 饱和度 `≥ 0.15` | 饱和度强制钳到 `0.60–0.88`，明度强制钳到 `0.78–0.94` |
| 色相 | 主色色相 `-40° / 0° / +40°`，明度倍率 `0.88 / 1.0 / 0.94` |

具体后果：

1. **单色相。** 整页永远是同一色相家族的三团光，相当于“把封面主色换个亮度铺开”，
   缺少封面本身的色彩构成。这是“只取单色”的直接结果。
2. **原色被抹掉。** `#1B224A`（深蓝）、`#3C211D`（暗棕）这类暗封面会被拉到高明度高饱和，
   色相还在，但明暗关系没了，观感不再像原封面。
3. **灰阶封面换默认色。** `#888886` 这种封面直接变成青绿、亮蓝、紫，与封面完全无关。
4. **露出面积有限。** 光晕整层只有 0.62 不透明度，内容区还有大量不透明卡片，
   实际能看到的只有边缘、侧栏缝隙和页面留白，关联感进一步减弱。

`docs/ambient-color.md` §4.3 / §4.4 当时决定“灰阶封面不凭空染色”“不放松派生范围”，
本次需要推翻这两个结论：用户的原话是“类似 Mica 对图片取色处理的最终效果”，
说明他要的是**由封面真实色彩构成的氛围**，而不是一套精修过的固定渐变。

### 3.4 歌词页已实现的部分

歌词页当前已有完整的四模式背景，可复用性如下：

| 能力 | 位置 | 外壳可直接复用 |
| --- | --- | --- |
| 模式枚举 | `LyricsBackgroundMode` | 语义不同，需新建外壳枚举 |
| 选图 + EXIF 摆正 + 1920 上限 + PNG 重编码 | `LyricsPage.xaml.cs` 选图流程 | 可抽取为共享服务 |
| 裁剪交互 | `Controls/ImageCropView` | 是，独立控件 |
| 色盘 | `LyricsPage.xaml.cs` 内的 HSV 色盘弹窗 | 可抽取为共享弹窗 |
| 图片渲染 + 暗度 + 模糊 | `Controls/LyricsBackdrop`（Win2D） | 渲染器可参考，但外壳不应常驻 60fps 合成表面 |
| Mica 切换 | `MainWindow.SetLyricsMaterialBackdrop` | 需要提升为统一背板协调器 |
| 纯色跟随封面 | `ColorPalette.SolidBackground(seeds, theme)` | 是，按主题取深色/浅色 |

## 4. 方案总览

引入一个“背板档位”的概念。同一时刻只有一种背板生效，每种背板决定四件事：

| 背板模式 | 窗口 `SystemBackdrop` | 外壳底色层 | 外壳背景层 | 亚克力档 |
| --- | --- | --- | --- | --- |
| 封面取色 | 无 | 保留 | `AmbientBackdrop` | 现状 |
| Mica（仅 Win11） | `MicaBackdrop` | 隐藏 | 隐藏 | 降低 tint，让材质透出 |
| 自定义图片 | 无 | 保留（图片下方兜底） | 图片层 | 提高 tint，压住照片细节 |
| 纯色 | 无 | 隐藏或由纯色层覆盖 | 纯色层 | 现状 |
| 歌词 / MV 沉浸 | 由沉浸页决定 | 隐藏 | 隐藏 | 跟随沉浸页背板 |

## 5. 背景模式下沉到外壳

### 5.1 模式定义

新增 `ShellBackgroundMode`：

```csharp
public enum ShellBackgroundMode
{
    CoverAmbient = 0,  // 封面取色（沿用现有氛围光晕）
    Mica = 1,          // 系统 Mica，仅 Windows 11
    CustomImage = 2,   // 自定义图片
    SolidColor = 3,    // 纯色
}
```

不复用 `LyricsBackgroundMode`：歌词页的“封面模糊”和外壳的“封面取色”不是同一种渲染，
枚举混用会让两边的分支判断互相污染。

### 5.2 设置与持久化

新增 `ShellBackgroundSettings` 与 `JsonShellBackgroundSettingsStore`，文件
`%LOCALAPPDATA%/Bowen/shell-background.json`，独立于 `theme.json`：

- 背景模式与一张图片的路径、裁剪、暗度、模糊是同一组偏好，拆出去与 `LyricsSettings` 的拆分理由一致。
- 不扩 `ThemeSettings`：那是外观档位与启动页，混入图片路径会让“主题”这个概念变重。
- 默认值 `CoverAmbient`，升级后行为与现在一致（观感会因算法改进变化，见 §11）。

字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `Mode` | string | 四种模式，默认 `CoverAmbient` |
| `ImageFile` | string | 仅文件名，位于 `backgrounds` 目录 |
| `ImageDim` | number | 0–0.8，默认 0.5 |
| `ImageBlur` | number | 0–40 DIP，默认 0 |
| `FocusX` / `FocusY` | number | 0–1，默认 0.5 |
| `Zoom` | number | 1–3，默认 1 |
| `SolidColorArgb` | number | `0xAARRGGBB` |
| `SolidColorAuto` | bool | 是否跟随封面取暗色 |

`Normalized()` 与现有设置保持同一形状：逐项夹取，枚举非法时回默认，文件名只保留
`Path.GetFileName`，拒绝目录穿越。

### 5.3 统一背板协调器

Mica 是窗口级属性，现在由 `MainWindow.SetLyricsMaterialBackdrop` 独占写入。加入外壳 Mica 后，
必须保证**只有一个地方写 `SystemBackdrop`**，否则歌词页进出沉浸态会和外壳模式互相覆盖。

新增 `BackdropCoordinator`（或放在 `MainWindow` 内的私有解析方法），输入：

- 外壳背景模式；
- 是否处于沉浸态；
- 沉浸页自己请求的背板（当前只有歌词页会请求 Mica）。

解析结果：

| 条件 | 结果 |
| --- | --- |
| 沉浸态 | 完全交给沉浸页，外壳层全部隐藏 |
| 非沉浸 + `CoverAmbient` | 无系统背板；底色层与氛围层可见 |
| 非沉浸 + `Mica` 且系统支持 | `MicaBackdrop`；底色层与氛围层隐藏 |
| 非沉浸 + `Mica` 且系统不支持 | 回退 `CoverAmbient`；设置页选项置灰并提示需要 Windows 11 |
| 非沉浸 + `CustomImage` | 无系统背板；图片层可见 |
| 非沉浸 + `SolidColor` | 无系统背板；纯色层可见 |

调用点收敛为三处：启动加载设置、设置页改模式、进入/退出沉浸态。
`SetLyricsMaterialBackdrop` 改造为向协调器提交“沉浸页请求”，不再直接改窗口属性。

### 5.4 各模式的实现

**封面取色**：复用 `AmbientBackdrop`，只替换 `ColorPalette` 的输入（见 §6）。
窗口最小化、隐藏、沉浸时继续走 `IsResourceSuspended`，不新增常驻成本。

**Mica**：`MicaBackdrop { Kind = MicaKind.Base }`。进入 Mica 前先等沉浸入场动画结束的逻辑
只属于歌词页；外壳模式可以立即切换。Win10 上保证 `IsMicaSupported` 为假时永不设置。

**纯色**：一层 `SolidColorBrush`。深色与浅色主题各有一组独立预设，手动色也分别保存；
跟随封面时用 `ColorPalette.SolidBackground(seeds, theme)` 按主题映射表面色。
歌词页的纯色取色同样改用这条管线，但固定传 `AmbientTheme.Dark`。

**自定义图片**：见 §8。

### 5.5 与沉浸页的关系

- 进入歌词页或 MV 页的沉浸态时，`SetShellSurfaceVisible(false)` 已经隐藏外壳，
  协调器同时撤掉外壳背板请求。
- 歌词页自己选 Mica 时，窗口背板由歌词页请求决定；退出沉浸后回到外壳模式。
- 外壳模式与歌词页模式互不读写，避免“歌词页选了 Mica，退出后外壳也被改成 Mica”。

## 6. 封面取色改进

### 6.1 从单主色改为多色提取

新增 `ColorQuantizer.Palette(bgra, count)`，返回 2–3 个**封面里真实存在的颜色**：

1. 沿用现有 4 位分桶与桶内平均色。
2. 沿用现有彩色候选筛选：面积 `>= max(18, 0.5%)`、**OKLCH 彩度 `>= 0.025`**、亮度 `0.10–0.92`。
   用绝对彩度而不是 HSV 饱和度：浅粉 `#F7DCE3` 的饱和度只有 0.11，但彩度约 0.031，
   白底封面上的彩色条靠这条才能进入种子。
3. 按 `sqrt(count) * suitability` 排序。
4. 贪心选取：
   - 先取最高分；
   - 之后只接受与已选颜色的色相距离 `>= 24°`（环形）的候选；
   - 不足 3 个时把色相距离放宽到 `15°`，再不足则只看通道差 `>= 32`，避免重复色；
   - 通道差阈值的依据：实测橙红封面上两个 RGB 只差 29 的橙色会同时入选，第三个种子变成重复色。
5. 彩色候选不足 3 个时，用**低饱和度但真实存在**的桶补位，而不是凭空派生色相。
6. 完全没有彩色候选（灰阶封面）时，取封面里明暗不同的 2–3 个中性色，
   例如暗部、中间调、亮部；不再返回固定默认配色。

预期结果：一张棕蓝封面的三团光是棕与蓝，而不是同一种棕的三个亮度。

### 6.2 按主题映射明度与彩度

`ColorPalette.Ambient(seeds, theme)` 在 **OKLCH** 空间里映射，而不是 HSV：

- **色相**：原样保留，不再做 ±40° 偏移。
- **明度**：按主题取目标区间，而不是照搬封面自身的明暗。
  - 浅色主题：`0.78–0.90`；
  - 深色主题：`0.60–0.74`。
- **彩度**：
  - 浅色主题：`0.04–0.10`；
  - 深色主题：`0.07–0.15`，保证在深底上仍能读出色相；
  - 中性种子（OKLCH 彩度 `< 0.035`）彩度上限 `0.015`，保持灰调。
- 三团分别加 `-0.03 / +0.02 / -0.01` 的明度偏移，叠出层次。
- 目标彩度超出 sRGB 色域时二分降低彩度，保持明度与色相。

**为什么换成 OKLCH**：HSV 压低 `V` 会把绝对彩度一起压掉，深色主题下颜色会发灰发浑；
OKLCH 的明度与彩度解耦，可以单独抬高明度而保住颜色。这与 Material 3 的做法一致：
深色底上的角色色要比浅色主题更亮，否则色相读不出来。

这些常数只是起点，需要在真机上用固定样本集调；调参标准是“十个封面并排放，
深色与浅色下都能对应上封面”，而不是“单张好看”。

### 6.3 灰阶封面不再跳默认配色

- 真正灰阶的封面：用封面自身的灰调生成低饱和氛围（饱和度上限约 `0.12`），
  得到灰、暖灰、冷灰，而不是青绿蓝紫。
- 浅色低饱和封面：同样保留自身色相与明度，不再走默认。
- `DefaultAmbient` 只保留给三种情况：**没有封面地址、解码失败、封面全透明**。
  这三种情况与“封面是灰色”在观感上必须有区别。

### 6.4 封面纹理层（暂不做）

**2026-10-31 决定：先只做多色光晕，不加纹理层。** 保留为后续选项：

- 取 24×24 或 32×32 的封面缩略图，直接拉伸铺满窗口，
  叠在底色层与光晕层之间，不透明度 `0.10–0.18`。
- 不运行时模糊：小图双线性放大本身就是柔和的色块，成本几乎为零。
- 效果接近 Mica 的“模糊壁纸”质感，颜色与构图都直接来自封面。
- 如果阶段 A 的多色光晕仍显得不像封面，再考虑叠加，并暴露成 0–30% 的滑杆。

### 6.5 诊断日志

沿用现有日志，补充一行分支信息：候选数量、最终选中的颜色、是否走了灰阶分支、
是否有纹理层。`docs/ambient-color.md` §4.6 一直未做的诊断日志在这里一并补上。

## 7. 亚克力与 Mica 的协调

### 7.1 现状

所有磨砂表面共用 `AcrylicMaterial` 里的两个刷子：

| 主题 | TintColor | TintOpacity | TintLuminosityOpacity | FallbackColor |
| --- | --- | --- | --- | --- |
| 浅色 | `#FFFFFF` | `0.35` | `0.6` | `#FAFAFA` |
| 深色 | `#202020` | `0.4` | `0.35` | `#202020` |

这两个档是按“深色实底 `#121212` 或氛围渐变”调出来的：tint 是中性灰，
目的只是把卡片与渐变底区分开。

### 7.2 直接叠在 Mica 上的问题

- Mica 本身就是“壁纸模糊 + 色调”。亚克力再叠一层，等于二次模糊 + 中性灰 tint，
  深色下容易发浑，卡片变成一块脏灰。
- 浅色 Mica 接近白，`0.35` 的白色 tint 会让卡片几乎消失，只剩边框。
- Mica 的颜色随桌面壁纸变化，卡片的对比度不可控；壁纸花哨时文字对比度会下降。
- 用户把背景设成 Mica 的意图是“让窗口融入桌面”，卡片却把它整片盖住，会互相打架。

### 7.3 方案：按背板模式切换亚克力档

在 `AcrylicMaterial` 里增加 `ApplyBackdrop(BackdropKind)`，只改两个刷子的几个属性，
所有引用同一刷子的表面会一起更新：

| 背板 | 浅色 tint | 深色 tint | 说明 |
| --- | --- | --- | --- |
| 封面取色 | 白 `0.35` / 亮度 `0.6` | `#202020` `0.4` / 亮度 `0.35` | 保持现状 |
| 纯色 | 同现状 | 同现状 | 低对比底色，无需调整 |
| 自定义图片 | 白或深色 `0.55–0.65` | `0.55–0.65` | 照片细节多，卡片要更实才能压住 |
| Mica | 白 `0.18–0.25` / 亮度 `0.5` | `#202020` `0.2–0.28` / 亮度 `0.3` | 让材质透出来，避免二次浑浊 |

原则：

- **只调 tint 与亮度，不换刷子实例**，避免已经引用的 XAML 资源失效。
- 设置里关闭亚克力时仍走 `AlwaysUseFallback`；兜底色保持不透明，无论背板是什么都清晰。
- 高对比度主题永远用系统实色，不参与这套切换。
- 沉浸页若自己选了 Mica，同样应用 Mica 档；切走后恢复外壳背板对应的档。

### 7.4 需要验证的点

- 应用主题（强制浅色 / 强制深色）与系统 Mica 的明暗是否一致。
  如果 `MicaBackdrop` 跟随系统而不是应用主题，强制深色下会出现浅色背板配深色卡片，
  需要在真机上确认，必要时改用 `MicaController` 显式设置主题。
- 浅色 Mica 下卡片边框是否足够可见；如果不够，给卡片补 1px 低对比描边，
  而不是继续加大 tint。
- Win10 没有 Mica，只验证“置灰 + 回退封面取色”这一条路径。

## 8. 自定义图片

### 8.1 导入与存储

歌词页与外壳共用一个 `BackgroundImageStore`：

- 输入：`StorageFile`；
- 处理：按 EXIF 摆正、最长边缩到 1920、重编码为 PNG；
- 存储：`%LOCALAPPDATA%/Bowen/backgrounds/`，外壳图片用 `shell-` 前缀；
- 替换：写入新文件成功后再删除旧文件；取消裁剪则删除刚写入的临时文件；
- 返回：文件名，交给设置模型持久化。
- 亮度估算也在这里：按平均亮度给出初始遮罩强度，亮图多遮、暗图少遮。

歌词页原来的选图、EXIF 处理与亮度估算已经改为调用这个服务，行为不变。

### 8.2 裁剪比例

- 裁剪对话框抽成 `BackgroundCropDialog`，按**目标宽高比**调用；
- 外壳传窗口内容区的宽高比，歌词页传背景层的宽高比；
- **100% 正好铺满目标区域，不做额外放大。** 预览与最终渲染必须使用同一基准；
  多出来的 10% 系数会让用户框住的区域与实物对不上，歌词页的渲染也一并去掉。
- 窗口比例变化后按 `UniformToFill` + 焦点 + 缩放重新取景；
- 默认居中、100%；暗度按图片平均亮度给初值，外壳默认 50%。

### 8.3 渲染

- 新增 `ShellImageBackdrop`：一次性把取景与模糊渲染成一张位图，再由普通 `Image` 铺满；
- 源图与输出位图最长边都压到 1280；模糊在这一次渲染里完成，不常驻模糊效果链；
- 渲染结束释放源图、渲染目标与设备租约，静止时只保留一张约 4–6 MB 的位图；
- **不在控件内部裁剪，也不手写 Width/Height/位移**；`UniformToFill` 保证任意窗口比例都铺满，
  多出的部分交给父层裁掉，不会再出现右侧或底部的缝；
- 模糊 0–40 DIP，默认 16；拖动防抖 150 ms，避免一拉就连续整窗渲染；
- 窗口尺寸变化防抖 150 ms 后重渲染，期间旧位图由 `UniformToFill` 覆盖。

## 13. 验收清单

### 取色

- 白底彩色主体、黑底彩色主体、浅色、深色、灰阶、双色封面各准备若干张。
- 同一张专辑连续播放颜色稳定；切歌有 650ms 过渡；快速连切不跳旧色。
- 灰阶封面得到灰调背景，不再出现青绿蓝紫。
- 深色主题下暗封面不发灰发浑，浅色主题下颜色不刺眼。
- 日志能看出候选、选中色与分支。

### 背景模式

- 四种模式互斥，切换无白闪、无残留层。
- Mica 仅 Win11 可选；Win10 置灰并回退封面取色。
- 自定义图片在窗口缩放、最大化、还原后不露边、不拉伸变形。
- 纯色跟随封面切歌时更新；手动色不被切歌覆盖。
- 进入/退出歌词页、MV 页后外壳背景正确恢复。
- 最小化、隐藏到托盘、恢复后背景正常，无重复解码。

### 亚克力与 Mica

- Win11 浅色 / 深色、系统浅色 / 深色、应用强制浅色 / 强制深色交叉检查。
- Mica 下卡片不浑、不发灰，文字对比度足够；浅色下卡片仍能看出边界。
- 关闭亚克力后，所有背板下都是实色兜底，不出现半透明叠半透明。
- 高对比度主题不受影响。

### 资源

- 静止时 CPU 与当前版本持平；最小化后不持续重绘。
- 自定义图片只保留一张解码位图；切换模式后旧位图被释放。
- 内存相对当前版本的增量在可接受范围，记录实测数字。
