# 小窗（迷你播放器）实现与验收

**状态：2026-10-06 长歌词横向滚动已实现，用户已验收；基础实现于 2026-10-05 验收。**

入口是标题栏主题按钮左边那颗「小窗」。点开后是一个独立的浮动条，形态与透明底座全部复用桌面歌词那一套
（无边框、逐像素透明、置顶、可拖动、边缘吸附、光标轮询），差别只在内容与「贴边收起」这条新行为。
底座的实测记录见 [`tech-stack.md`](tech-stack.md) 的透明悬浮窗一节。

---

## 1. 入口与外观

| 项目 | 当前行为 |
| --- | --- |
| 入口 | 标题栏 `RightHeader`，主题按钮左侧（分隔线之前）；32×32，与账号／主题按钮同一中心线；开着时显示激活态 |
| 打开时主窗口 | **保持不动** —— 不最小化、不隐藏、焦点不变。两个窗口同时开着 |
| 尺寸 | 固定 **360 × 64 DIP**，不可拉伸、不可最大化最小化。字号相应收小（歌名与歌词 13、歌手与音量数值 11） |
| 圆角 | 12 DIP，**真抗锯齿圆角**（见 §3），窗口四角随面板方向重新分配 |
| 主题 | 跟随应用主题（根元素 `RequestedTheme` 绑 `ThemeViewModel.RequestedTheme`），卡片底色用 `CommentPanelBackgroundBrush` |
| 封面 | 64 × 64，与窗口左边缘齐平、占满整条高度；**左上下两角跟随窗口圆角，右侧两角是直角** |
| 内容条右侧 | 收藏 ❤ / 音量 🔊 / 播放队列 ☰；最右一列 ✕ 在上、▢ 在正下方 |
| 进度 | 条的最下沿一条 2 DIP 细线，从封面右沿铺到右端（留出圆角那 12 DIP）。**不画拇指**，命中区仍是整条，按住拖动可跳转 |

### 信息区的三种状态

内容条中间那块位置按优先级切换，三层叠在同一格、靠 `Visibility` 换，不占额外空间也不会让布局跳：

| 条件 | 显示 |
| --- | --- |
| 鼠标在窗口内 | 上一首 / 播放暂停 / 下一首 |
| 否则播放中且有歌词 | **一行歌词**（短句居中，长句保持 13 DIP 字号随播放横向滚动） |
| 否则（暂停 / 没有歌词） | 歌名 + 歌手 |

悬浮时曲名并没有消失 —— 它挪到悬停抽屉里去了（§2）。

传输区的上一首／下一首绑 `CanGoPrevious`／`CanGoNext`（与播放条同一套判据），队列到头时置灰。
置灰后它们**不再可命中**，所以拖窗的判定要单独把整块传输区排除掉，否则点上去会变成拖窗（§9.2）。

## 2. 悬停抽屉

鼠标进入窗口时，内容条下方（**固定向下**）弹出一条小抽屉显示歌名与歌手。

| 项目 | 行为 |
| --- | --- |
| 方向 | **永远向下**。与队列面板不同，抽屉不挑方向 |
| 高度 | 36 DIP。**一行就够**（歌名 + 歌手并排，居中），两行那种块状抽屉在 64 DIP 的横条旁边显得很重 |
| 收起 | **鼠标离开立即收起**，不留宽限 —— 它是悬浮时的附加信息，不是常驻面板 |
| 与队列面板 | 互斥。队列面板开着时不弹抽屉 |
| 与内容条 | 中间无间隙，连成一块（同 §5） |

### 音量：点击弹出的横向小滑块

点 🔊 在按钮**正上方**弹出**横向**滑条（`🔊 ———⬤——— 65%`），宽 140 DIP。
朝上是因为下方要留给歌名抽屉与队列面板。

**三件事缺一不行：**

1. **用 `Flyout` + `Placement="Top"`**，挂在按钮上，点击自动弹、点外面自动收。
   **不复用 `VolumeButton`** —— 那个控件弹出的是一条竖直滑条，在 64 DIP 高的小窗上会被裁掉
   （`VolumeButton.xaml` 里还有一条「任何宿主页都不许改成横向滑条」的约束，小窗因此另起一颗，不动那个控件）。
   两者共用同一个 `PlayerViewModel.Volume`，所以三处音量仍然是一个值。
2. **`ShouldConstrainToRootBounds="False"` 不能省。** 它默认是 `true`，含义是「弹层必须待在应用窗口内」；
   而这条弹层比窗口还高，上方根本放不下，于是 `Placement="Top"` 会被**翻转成朝下**。
   置为 false 才允许它落到窗口外面。（先试过自定位 `Popup` + 负偏移，不行 —— 同样被窗口裁掉。）
3. **弹层开着时窗口要钉住**（`_flyoutOpen`，与队列面板同一套）。弹层在窗口外面，鼠标得移出去才够得着；
   不钉住的话，鼠标一离开就翻转悬停态 → 抽屉收起 → 窗口从 100 DIP 缩回 64 DIP →
   **Flyout 随宿主窗口改尺寸被重新定位甚至直接关掉**，症状是「弹出来了但点不到，一下就没了」。
   关闭弹层时再按当前状态重算一次布局。

方向固定的代价：条贴在屏幕最下方时抽屉没有空间，那时只显示传输按钮、没有歌名。

## 3. 透明、圆角与置顶

复用本机验证过的组合，逐条见 [`tech-stack.md`](tech-stack.md) 的透明悬浮窗一节：

1. `OverlappedPresenter.SetBorderAndTitleBar(false, false)` 去掉标题栏与边框。
2. 扩展样式加 `WS_EX_LAYERED | WS_EX_TOOLWINDOW`；清 `WS_CAPTION | WS_THICKFRAME` 后再 `SetWindowPos(SWP_FRAMECHANGED)`。
3. `TransparentBackdrop` 做 DWM 扩帧、blur-behind，并拦下 `WM_ERASEBKGND` 自己填黑。
4. 500 ms 定时器只在 `WS_EX_TOPMOST` 丢失时才 `SetWindowPos(HWND_TOPMOST, …, SWP_NOACTIVATE)`。
   拖动中与面板打开时不重排。

**两处与桌面歌词不同的决定：**

| 项 | 小窗 | 理由 |
| --- | --- | --- |
| `WS_EX_NOACTIVATE` | **不加** | 桌面歌词加它是因为那张窗纯展示。小窗里有音量 Popup 和一堆要点的按钮；无焦点的悬浮窗上原生弹层会抢占／丢失指针捕获（桌面歌词踩过，它的解法是把面板留在窗口内），而 `VolumeButton` 是现成控件、不许改成横向滑条 |
| 圆角 | **靠 XAML 的 `CornerRadius`** | `DWMWA_WINDOW_CORNER_PREFERENCE` 在 Win10 返回 `E_INVALIDARG`（Win11 22000+ 专有）。窗口本身逐像素透明，圆角以外什么都不画就得到抗锯齿圆角，不需要 `SetWindowRgn`（有锯齿，且弹层一出现就得手工改区域） |

仍会调一次 `DwmSetWindowAttribute(DWMWCP_DONOTROUND)`，只为「别让 Win11 再叠一层系统圆角／细边框」；
Win10 上失败是预期内的。

**封面圆角怎么来的**：图片走 `Border.Background` 的 `ImageBrush`，**不是** `Border` 的子元素 ——
`Border` 的圆角只裁自己的背景画刷、不裁子树，写成 `<Border CornerRadius=".."><Image/></Border>`
出来是直角封面。这是「圆头像」的标准做法，声明式、不用 `CompositionGeometricClip`。

打开小窗不抢焦点：首次 `Activate()`（不然窗口不开始渲染），之后一律 `AppWindow.Show(activateWindow: false)`。

## 4. 拖动与贴边收起

### 拖动

与桌面歌词同一套：位移一律用**光标屏幕坐标**算，移动时 `DesktopLyricsWindowGeometry.Constrain`
做四边 16 DIP 吸附，跨屏取光标所在显示器的可用区域。按下即解贴边，鼠标一移窗口就跟手走。

两条差别：**队列面板打开期间禁止拖动**（面板开着时窗口很高，可拖区域太大容易误触，按下会先关面板）；
**拖动期间不弹抽屉**（边拖边改窗口尺寸会互相打架）。

### 贴边收起

| 状态 | 屏幕上的样子 |
| --- | --- |
| 自由 | 完整小窗 |
| 贴左收起 | 贴住工作区左边的一条 8 DIP 窄条 |
| 贴右收起 | 贴住工作区右边的一条 8 DIP 窄条 |
| 悬停临时展开 | 贴边那一侧不动，宽度恢复 420 DIP |

- **触发**：松手时内容条的外边缘与工作区左／右边**重合**即收起。不另立吸附阈值 ——
  `Constrain` 已在拖动过程中把窗口吸到边缘，所以「重合」等价于「距边缘不超过 16 DIP」。
  只有左右能触发，上下贴边不收起。
- **收起是改宽度，不是把窗口推出屏幕**。推到屏幕外露出来的是窗口自己的边缘内容
  （贴左时是 ✕/▢ 按钮列，贴右时是封面左沿），既不是设计过的把手，切口也是硬边；
  而且负坐标要参与所有几何运算，部分多屏与 DPI 组合下系统还会钳制完全移出工作区的窗口。
- **唤起**：30 ms 光标轮询。光标落在「贴边侧工作区边缘往内 8 DIP、纵向覆盖条高并在上下各放宽 8 DIP」
  的唤醒区里就展开。不用整条屏幕边做热区，否则鼠标一碰屏幕边缘就弹窗。
- **回弹闩锁**：收起的那一刻把 armed 置 false，光标**离开唤醒区一次**之后才重新武装 ——
  不然光标还停在原处，下一帧立刻又展开，来回抖。
- **收起后窄条整条开着 `WS_EX_TRANSPARENT`**：它贴在屏幕边上、整条高度，不穿透就会吃掉
  下面那个窗口在这一条上的点击。
- **展开态悬停离开约 200 ms 才收起**（抽屉是立即收，窗口收起不是）。

### 有意不做窗口动画

收起／展开是 `AppWindow.MoveAndResize` 的瞬时跳变。`MoveAndResize` 不是合成器驱动的，
每调用一次都要重排 HWND 并让 DWM 重新合成这块逐像素透明表面 —— 30 帧动画就是 30 次全窗重合成，
抖动与撕裂必现，还会和 `WS_EX_TRANSPARENT` 的开关打架。**这是取舍，不是没做完。**

## 5. 播放队列面板

点 ☰ 展开，复用 `Controls/PlayQueuePanel` 与单例 `PlayQueueViewModel`。

- **方向自适应**：下方放得下就向下，放不下且上方放得下就向上；两边都不够时选空间大的一边并把面板压小，
  压到 120 DIP 以下就干脆不打开。判据与常量见 `MiniPlayerGeometry.PlanPanel`。
- **条本身的屏幕位置一动不动**，只是窗口在某个方向上变高。向上展开时窗口的 `Y` 变小、条落在底行。
- **面板开着时窗口被钉住**：不收起、不唤起、禁止拖动。
- **面板与小窗连成一块**：中间没有间隙（`PanelGapDip = 0`），接缝处两侧都是直角，
  圆角只在整块外形的最外两头。面板自带标题行，不需要额外的分隔线。
- 面板与小窗同宽（同一列），衔接处的圆角由 `ApplyChrome` 按方向统一改，
  三个卡片（条 / 面板 / 封面兜底）必须一起改，否则会露出两个直角。

**与主窗口抽屉共用一份开关时会出两个 bug**，所以 `PlayQueueViewModel` 有两个开关：
`IsOpen` 归主窗口抽屉，`IsMiniPlayerOpen` 归小窗面板，`RefreshIfOpen` 两者任一为真就重建。
共用一个 bool 会让「点小窗的 ☰ 把主窗口抽屉也拉开」；反过来完全不改，面板里显示的是陈旧队列。

## 6. 歌词

小窗在播放时那一行位置显示当前歌词，所以它也是歌词的消费者：
`LyricsViewModel.IsMiniPlayerOpen` 与歌词页的 `IsOpen`、桌面歌词的 `IsDesktopLyricsOpen` 并列，
三者任一为真就取词。

```csharp
private bool IsActive => IsOpen || IsDesktopLyricsOpen || IsMiniPlayerOpen;
```

歌词显示用 `LyricsPlaybackClock` 在文档时间轴定位当前句。文字放在有裁剪范围的 `Canvas` 中，保持完整自然宽度和 13 DIP 字号：短句居中，长句随音节时间向左滚动，逐行歌词按本行时间推进，换句或跳转重新定位。只有可见且播放中的长句订阅 `CompositionTarget.Rendering`；悬停切换传输按钮、贴边收起、暂停和隐藏都取消逐帧回调。

## 7. 位置、开关与退出

| 文件 | 保存内容 | 实现 |
| --- | --- | --- |
| `%LOCALAPPDATA%\Bowen\mini-player-window.json` | 内容条的 X、Y | `MiniPlayerPlacementStore` 转发到独立路径的 `JsonWindowPlacementStore` |

- **只记位置，不记贴边收起**：收起是临时让路的状态，重启后小窗应该看得见，
  而不是缩在屏幕边上让人以为丢了。载入后起始状态一律「自由」。
- **尺寸不记**：它是固定的，记下来只会和内容打架。
- **开关不落盘**：上次退出时开着不代表这次启动就该冒出一个浮窗。
- 没有记录时落在主屏右下角、距工作区右／下各 24 DIP（桌面歌词用的是底部居中，两者不冲突）。
- 三个窗口几何（主窗口 / 桌面歌词 / 小窗）各占一个文件，共用会互相覆盖。

✕ 只关小窗，主窗口状态完全不变。▢ 先 `SetForegroundWindow` 抢前台、再隐藏自己 ——
`SetForegroundWindow` 要求调用进程是前台进程，反过来先隐藏，前台可能落到别的应用上、调用被拒，
症状是「点了 ▢ 主窗口没起来」。

主窗口关闭即退出应用，小窗一并销毁（`App.xaml.cs` 的 `Closed` 里 Dispose `MiniPlayerWindowHost`）。

## 9. 实施时踩到的坑

### 9.1 三个 XAML 解析期的坑

三个都**构建通过、启动才炸**，而且都表现为「点了按钮什么都没发生」——
宿主把异常记进日志并把开关置回 false，所以症状是按钮闪一下又弹回去。

| 坑 | 症状 | 结论 |
| --- | --- | --- |
| 引用 `{StaticResource PlayerProgressSliderStyle}` | `Cannot find a Resource with the Name/Key PlayerProgressSliderStyle` | 那是 `PlayerBar.xaml` 的**局部资源**，窗口这一层取不到。细进度条样式在小窗自己的 `Grid.Resources` 里另写一份 |
| 封面容器没有尺寸 | 封面那一列宽度为 0，封面整块看不见 | `Border` 只画背景时没有期望尺寸，Auto 列会塌成 0。宽度必须显式给 |
| 把宽度写在 `ColumnDefinition.Width` 上 | `the type 'Windows.Foundation.Double' cannot be assigned to the type 'Microsoft.UI.Xaml.GridLength'` | 列宽是 `GridLength`，接不了 `<x:Double>` 令牌（`SizePlayerBar`）。宽度写在**元素自己**的 `Width` 上，列保持 `Auto` |

排查手法：`%LOCALAPPDATA%\Bowen\logs\` 里搜 `[ERR] 小窗创建或显示失败`，紧跟的就是异常正文与出错的行号。

同一类风险的自查办法：把小窗 XAML 用到的资源键与 `PlayerBar.xaml` / `MainWindow.xaml` / `DesktopLyricsWindow.xaml`
用过键取差集 —— 差集里只剩下「本窗口自定义的样式」与「本窗口新加的图标键」，就说明没有别的取不到的键了。

### 9.2 交互层的三个坑

这几个**不报错、日志干净**，只能靠观察，比上面那三个难查。

| 坑 | 症状 | 结论 |
| --- | --- | --- |
| `Flyout` 默认被限制在窗口内（§2） | 弹层朝下，盖住歌名抽屉 | 置 `ShouldConstrainToRootBounds="False"`；且弹层开着时窗口要钉住 |
| 进度条的指针事件走 XAML 声明 | **拖得动，但进度不受影响** | `Slider` 内部把指针事件标记为已处理，XAML 上的 `PointerPressed` 收不到。必须 `AddHandler(..., handledEventsToo: true)`（与 `PlayerBar` 同一条路） |
| 传输按钮禁用后，点击穿透成拖窗 | 队列到头时按「下一首」，窗口被拖走了 | 禁用的按钮**不再可命中**，点在它身上其实落在下面的容器上 —— 只靠 `IsInteractiveSource` 查 `ButtonBase` 挡不住。按下时先判断落点是否在 `TransportPanel` 的矩形内，是就整块不参与拖窗 |

## 11. 已知边界

- 歌名抽屉**固定向下**，所以条贴在屏幕最下方时没有空间弹抽屉，那时只显示传输按钮。
- 进度条可拖动跳转（按下标记 `IsSeeking`、松开才 seek）。指针事件必须走
  `AddHandler(handledEventsToo: true)` —— Slider 内部会把指针事件标记为已处理，
  XAML 上的 `PointerPressed="…"` 收不到，症状是「拖得动但进度不受影响」。
  拇指是**画成透明**而不是尺寸给 0：给 0 会让 Slider 自己的拖动逻辑变脆。
- 收起／展开没有过渡动画，见 §4 的理由。
- 小窗不保证覆盖独占全屏的 D3D 应用（与桌面歌词同一条限制）。
- 窗口圆角外那几像素仍在窗口矩形内，点击不穿透。四角各约 31 px²，不值得为它接穿透开关；
  **真正需要穿透的只有收起后的窄条**，那一条已经开着。
- Windows App SDK 升级后需要重新验证透明、置顶、圆角与贴边收起。
